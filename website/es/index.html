Instalar

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
$ ling-admin server start      # descarga el modelo una vez (~20 GB) y luego lo inicia
$ cd ~/your-project && ling    # eso es todo

Esto funciona en el NVIDIA DGX Spark y en cualquier otra máquina GB10. El script comprueba cada descarga con las sumas de verificación de la versión y te muestra cada comando sudo antes de ejecutarlo. Puedes leer el script antes.

Clientes para Mac y Linux

Tus otros ordenadores toman prestado el modelo del GB10 por la red de tu casa o tu oficina. En un Mac u otra máquina Linux, el mismo comando instala ling, la parte en la que escribes. Encuentra el GB10 por sí solo.

Desde la 1.7.2 también pone la aplicación de escritorio en Aplicaciones en un Mac, lista para abrir. Añade --no-app si no la quieres.

Cliente para Windows preview

> irm https://github.com/dreamference/mightling/releases/latest/download/install.ps1 | iex

Escribe esto en PowerShell. No necesita derechos de administrador (desde la 1.7.2 eso vale también para la aplicación de escritorio). Después Windows te pregunta una vez si quiere preparar un lugar aislado donde el ayudante ejecuta comandos. El instalador aún no está firmado, así que el Control inteligente de aplicaciones (Smart App Control) debe estar desactivado. Lee el script.

Otras formas de instalar

La página de la versión también tiene la imagen de disco para Mac (Mightling-<version>-arm64-preview.dmg, o x64 para Intel) y el instalador de Windows (Mightling-Setup-<version>-x64.exe, o arm64). Son versiones preliminares sin firmar, así que cuando las descargas en un navegador, tu sistema las detiene la primera vez. Antes de abrir una, compárala con el archivo firmado SHA256SUMS de la versión.

  • macOS 15 y posterior: arrastra Mightling a Aplicaciones y ábrelo una vez. Luego ve a Ajustes del Sistema › Privacidad y seguridad y pulsa Abrir igualmente. En macOS 14 y anteriores, haz clic con Control en la aplicación y elige Abrir.

Prueba esto primero

O deja trabajo para esta noche con /night add <task>. Mightling recorre la lista mientras duermes, cada tarea en su propia rama de git, y por la mañana revisas las ramas.

$ ling "explain this repository to me like I'm new on the team"
# reads the code index (ling-code outline, def, refs, callers) instead of grepping,
# then walks you through the layout, the entry points and how they connect
$ ling "the tests are failing: find out why and fix them"
# runs the tests, reads the failure, edits the code and runs the tests again,
# asking before anything risky
> /night add --best-of 3 add input validation to the signup form, with tests
# tonight: three attempts, each in its own git worktree; the one the chooser picks
# is committed on its own branch, and nothing is merged or pushed
$ ling-admin night status      # the timer, the window and the queue
> /night apply <id>            # in the morning: bring the branch back as uncommitted changes

Tu código se queda en tu escritorio, y puedes comprobarlo

Un ayudante de programación en la nube envía tu código fuente a ordenadores que son de otra persona. Mightling no lo envía a ningún sitio. El modelo funciona en tu GB10, y nada en Mightling llama a casa: ni contadores de uso, ni mediciones, ni inicio de sesión, ni siquiera informes de fallos «anónimos». Así puedes usarlo con código que no tienes permiso para subir, como el trabajo de un cliente, datos protegidos o un producto aún sin publicar.

Un comando ejecuta una sesión real de Mightling bajo strace, una herramienta que observa cada llamada que hace un programa, y luego lista cada conexión de red que abrió la sesión:

$ ling-admin audit egress
✔ Egress audit: pass
Network destinations:
   127.0.0.1:8000     29x  model server
   127.0.0.1:8767      1x  Gmail search service
DNS queries: none
Networked git commands: none

Todo se quedó en 127.0.0.1, que es la máquina hablando consigo misma. No hubo ni una sola consulta DNS (una consulta DNS es preguntar a internet la dirección de un nombre).

¿Quieres una garantía firme?

Escribe /airgapped on. Cada comando que ejecuta el ayudante recibe entonces una red vacía del kernel de Linux. No es una petición educada al modelo. Simplemente no hay red a la que llegar. Al mismo tiempo, se rechaza Full Access, que se saltaría el sandbox.

Qué puede salir, y cuándo

Solo lo que tú o el ayudante pides: una búsqueda web (a través de un SearXNG privado que funciona en tu propia máquina, aunque la búsqueda en sí sale a la web), la descarga de una página web, una petición de solo lectura a una cuenta de Google que hayas conectado, o una comprobación de actualizaciones. Con /airgapped on, nada de esto ocurre.

SWE-bench Verified, medido en un solo DGX Spark

SWE-bench Verified es un conjunto de 500 problemas reales tomados de programas de código abierto. En cada uno, el ayudante tiene que cambiar el código para que pasen las pruebas. El 2026-10-08 le dimos 100 de ellos a Mightling 1.5.1, con el modelo Qwen3.8-27B, en un solo DGX Spark sin internet. Tuvo un intento en cada uno, en su modo por defecto, y resolvió 68 de los 100. Si lo extendemos a los 500, estimamos cerca de un 69 %, con unos pocos puntos de margen (el intervalo del 95 % va del 63,9 al 73,4 %). Lo medimos nosotros mismos, en nuestra propia máquina, sobre una muestra de los problemas. No es una entrada de la clasificación oficial.

Lee esta tabla como una forma de ver quién está cerca, no como un ranking. En los mismos 100 problemas, Mightling resolvió tantos como Qwen3-Coder-480B y GLM-4.6, modelos muchas veces más grandes. Pero cada fila usa un programa ayudante distinto y un hardware distinto, y las filas de la clasificación usaron las imágenes de prueba oficiales para ordenadores x86, mientras que las nuestras corrieron en imágenes de la comunidad para arm64. Hay también un segundo modo, llamado refine. Una primera sesión estudia el problema y no cambia nada, y luego una sesión nueva hace el trabajo. Resolvió un problema más que el modo por defecto (69 frente a 68, y cada modo resolvió algunos que el otro no), y tardó unas 2,2 veces más en cada problema. Por eso está desactivado salvo que lo pidas con ling --refine.

Cómo estimamos el 69 %

100 problemas son una quinta parte de Verified, así que la cifra para los 500 es una estimación. Así la hicimos. Tomamos los resultados de las 175 propuestas públicas de Verified, problema por problema. Damos a cada problema una dificultad y a cada sistema una capacidad, con un modelo de respuesta al ítem (Rasch) de un parámetro. La capacidad de Mightling es la que resolvería 68 en estos 100 problemas, y cerca del 69 % es lo que esa capacidad lograría en los 500. Una regresión simple sobre las puntuaciones publicadas coincide con una diferencia de un punto. También comprobamos el método en otros: para cada propuesta pública usamos solo su puntuación en estos 100 problemas para predecir su puntuación en los 500. El error fue de 2,4 puntos (RMSE), y el intervalo de arriba es 1,96 veces eso a cada lado. Cada número de la tabla se puede reproducir con scripts/swe_bench_compare.py, a partir de los datos públicos por problema de SWE-bench/experiments.

Repartimos los 100 problemas entre los programas de Verified en las mismas proporciones que el conjunto completo. Los sacamos de los problemas cuya preparación de pruebas funciona y se comprueba en arm64 (la corrección correcta pasa, y no hacer nada falla). Los sistemas publicados puntúan entre 1,0 y 1,5 puntos menos en estos 100 que en los 500, así que la muestra no es fácil. Aun así no es una entrada de la clasificación, porque el equipo de SWE-bench las evalúa en sus propias máquinas.

FAQ

¿Necesito un GB10?

Sí, para ejecutar el modelo. Tus otros ordenadores son clientes que lo toman prestado: Linux (Arm o x86) y macOS con el mismo comando de instalación, y Windows (Arm o x86, versión preliminar) con la línea de PowerShell.

Instalé Puffin. ¿Es el mismo programa?

Sí. Puffin se renombró Mightling en la 1.5. Ejecuta puffin update una vez y luego puffin una última vez. Traslada tus sesiones, ajustes y enlaces, y después el comando es ling.

¿De verdad no cuesta nada?

Nada por el programa ni por el modelo. Mightling es de código abierto bajo la AGPL, y los pesos del modelo son de uso libre. Pagas la máquina y la electricidad que consume.

¿Qué necesito aparte de la máquina?

El sistema operativo que trae (DGX OS 7, o Ubuntu 24.04 donde NVIDIA lo ofrece), Docker con el NVIDIA Container Toolkit, Python 3 y Git. En un Ubuntu normal, ling-admin host check te dice qué falta.

¿Sale algo alguna vez a internet?

Solo lo que tú o el ayudante pides, como una búsqueda web (a través de un SearXNG que funciona en tu propia máquina) y las descargas del primer uso. Con /airgapped on, todo eso queda desactivado.

¿Qué modelo ejecuta?

Qwen3.8-27B, en el formato de 4 bits de NVIDIA llamado NVFP4, servido por SGLang con un pequeño ayudante que adivina, llamado drafter DFlash2. Elegimos y ajustamos todo para el GB10. Los pesos ocupan unos 20 GB, y mientras funciona quedan libres unos 38 GB de la memoria de la máquina.

Mantén tu código en tu escritorio

Si piensas que el código debe quedarse en el escritorio donde se escribió, dale una estrella al repositorio en GitHub. Así es como otros dueños de un GB10 encuentran Mightling.

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
