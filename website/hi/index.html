1.7.0 में यह भी है: Night Shift एक काम को कई बार आज़मा सकता है और सबसे अच्छी कोशिश रख सकता है (/night add --best-of N)। एक मशीन कई Signal ब्रिज चला सकती है। और जो कंप्यूटर एक नेटवर्क पर दो GB10 देखता है, वह उनमें से एक चुन सकता है, और जिसे वह पहले से जानता है उसे भूलता नहीं। रिलीज़ नोट्स और डाउनलोड।

इंस्टॉल

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
$ ling-admin server start      # मॉडल एक बार डाउनलोड होता है (~20 GB), फिर चालू हो जाता है
$ cd ~/your-project && ling    # बस इतना ही

यह NVIDIA DGX Spark पर चलता है, और हर दूसरी GB10 मशीन पर भी। स्क्रिप्ट हर डाउनलोड को रिलीज़ के चेकसम से मिलाकर जाँचती है, और हर sudo कमांड को चलाने से पहले आपको दिखाती है। आप चाहें तो पहले स्क्रिप्ट पढ़ सकते हैं।

Mac और Linux क्लाइंट

आपके बाकी कंप्यूटर घर या दफ़्तर के नेटवर्क से GB10 का मॉडल उधार लेते हैं। Mac या किसी दूसरी Linux मशीन पर यही कमांड ling लगाता है, यानी वह हिस्सा जिसमें आप टाइप करते हैं। वह GB10 को अपने आप ढूँढ लेता है।

1.7.2 से यह Mac पर डेस्कटॉप ऐप को भी Applications में रख देता है, खोलने के लिए तैयार। न चाहें तो --no-app जोड़ दें।

Windows क्लाइंट प्रीव्यू

> irm https://github.com/dreamference/mightling/releases/latest/download/install.ps1 | iex

इसे PowerShell में टाइप करें। इसके लिए एडमिनिस्ट्रेटर अधिकार नहीं चाहिए (1.7.2 से डेस्कटॉप ऐप के लिए भी यही है)। फिर Windows आपसे एक बार पूछता है कि एक दीवारों से घिरी जगह बना दे, जहाँ सहायक कमांड चलाता है। इंस्टॉलर पर अभी हस्ताक्षर नहीं हैं, इसलिए Smart App Control बंद होना चाहिए। स्क्रिप्ट पढ़ें।

इंस्टॉल करने के दूसरे तरीके

रिलीज़ पेज पर Mac की डिस्क इमेज (Mightling-<version>-arm64-preview.dmg, या Intel के लिए x64) और Windows इंस्टॉलर (Mightling-Setup-<version>-x64.exe, या arm64) भी हैं। ये बिना हस्ताक्षर के प्रीव्यू हैं, इसलिए ब्राउज़र से डाउनलोड करने पर आपका सिस्टम पहली बार इन्हें रोक देता है। खोलने से पहले इन्हें रिलीज़ की हस्ताक्षरित SHA256SUMS फ़ाइल से मिलाकर जाँच लें।

  • macOS 15 और उसके बाद: Mightling को Applications में खींचें और एक बार खोलें। फिर System Settings › Privacy & Security में जाएँ और Open Anyway दबाएँ। macOS 14 और उससे पहले में ऐप पर Control दबाकर क्लिक करें और Open चुनें।
  • Windows: SmartScreen › More info › Run anyway। Smart App Control बंद होना चाहिए।

पहले ये आज़माएँ

या आज रात के लिए काम छोड़ दें: /night add <task>। आपके सोते समय Mightling सूची पर काम करता है, हर काम अपनी अलग git ब्रांच पर, और सुबह आप उन ब्रांचों को देख लेते हैं।

$ ling "explain this repository to me like I'm new on the team"
# reads the code index (ling-code outline, def, refs, callers) instead of grepping,
# then walks you through the layout, the entry points and how they connect
$ ling "the tests are failing: find out why and fix them"
# runs the tests, reads the failure, edits the code and runs the tests again,
# asking before anything risky
> /night add --best-of 3 add input validation to the signup form, with tests
# tonight: three attempts, each in its own git worktree; the one the chooser picks
# is committed on its own branch, and nothing is merged or pushed
$ ling-admin night status      # the timer, the window and the queue
> /night apply <id>            # in the morning: bring the branch back as uncommitted changes

🧭 कोड इंडेक्स

आपके पूरे प्रोजेक्ट में चीज़ें कहाँ परिभाषित हैं और उन्हें कौन इस्तेमाल करता है, इसकी सूची, ताकि सहायक कोड को अंदाज़े से खोजने की जगह सीधे देख सके।

🔎 वेब सर्च और पेज लाना

सर्च आपकी अपनी मशीन पर चलने वाले निजी SearXNG से होती है, इसलिए कोई सर्च अकाउंट नहीं और कोई कुंजी लेने की ज़रूरत नहीं। सवाल फिर भी जवाब पाने के लिए वेब तक जाते हैं।

🌙 Night Shift

सोने से पहले /night add <task> टाइप करें। सुबह तक हर काम अपनी अलग git ब्रांच पर हो चुका होता है। जब तक आप ख़ुद न करें, कुछ भी मर्ज या पुश नहीं होता।

आपको क्या मिलता है

1.7.0 का डेस्कटॉप ऐप Mightling को इस्तेमाल करने के दोनों तरीक़े एक ही विंडो में लाता है: Ask, जहाँ आप सवाल पूछते हैं, और Work, जहाँ सहायक आपका कोड बदलता है। Work में काम लिखने का एक बॉक्स है (आप फ़ाइलें, स्किल और कमांड जोड़ सकते हैं), बदलावों को रखने या वापस लेने से पहले देखने का एक पैनल है, आपके कोड की अलग-अलग कार्यकारी प्रतियाँ (worktrees) हैं, टर्मिनल टैब हैं, और बातचीत के बगल में फ़ाइलों का पेड़ है। आपके दूसरे कंप्यूटरों पर ऐप आपके GB10 से बात करता है, जिसे वह आपके नेटवर्क पर ढूँढ लेता है।

ling · ling-code · ling-docs

🖥️ ling, आपके टर्मिनल में सहायक

यह आपका प्रोजेक्ट पढ़ता है, कमांड और टेस्ट चलाता है, कोड बदलता है, और कोई जोखिम भरा काम करने से पहले आपसे पूछता है।

इंस्टॉल →
$ ling worktree on   # new sessions start in their own worktree
$ cd ~/your-project && ling
> /airgapped on      # no network for any command it runs
> /worktree apply    # bring the changes back to your checkout

🧩 आपके पास जो स्किल हैं, वही काम आती हैं

Claude Code, Gemini CLI, OpenClaw या Hermes के लिए आपकी लिखी स्किल यहाँ जैसी हैं वैसी ही चलती हैं।

🪟 डेस्कटॉप ऐप प्रीव्यू

Ask और Work एक ही विंडो में, GB10, Mac, Linux या Windows पर। सहायक के सेशन आपकी मंज़ूरी माँगते हैं, और बदलाव देखने का पैनल, अलग-अलग कार्यकारी प्रतियाँ और पूर्ववत करने की सुविधा है। 1.7 में नया।

वेब सर्च, इमेज सर्च और टाइप करने की जगह बोलकर सवाल, और आपके सहायक सेशन भी, इस मशीन से या उस फ़ोन से जिसे आपने इसके साथ जोड़ा है। यह सब आपकी मशीन पर उसी मॉडल का इस्तेमाल करता है।

डॉक्स →

macOS प्रीव्यू

1.7.2 से इंस्टॉल कमांड Mightling को ling के साथ Applications में रख देता है, और आप इसे किसी भी दूसरे ऐप की तरह खोलते हैं। यह Apple silicon और Intel दोनों पर चलता है, macOS 12 या उसके बाद के साथ। ling update इसे अपडेट करता है।

Linux

GB10 पर mightling_1.7.0_arm64.deb फ़ाइल ऐप, उसकी मेन्यू एंट्री और ling-app कमांड को लगाती है, साथ में वह सैंडबॉक्स प्रोफ़ाइल भी जो इसे चाहिए। (सैंडबॉक्स कमांड चलाने का एक बंद कमरा है, ताकि वे मशीन के बाकी हिस्से को छू न सकें।)

$ sudo apt install ./mightling_1.7.0_arm64.deb

फिर इसे एप्लिकेशन मेन्यू से खोलें, या ling app टाइप करें। और जानें।

Windows 11 प्रीव्यू

1.7.2 से PowerShell की पंक्ति ऐप भी लगा देती है, सिर्फ़ आपके लिए और एडमिनिस्ट्रेटर अधिकार के बिना, Start मेन्यू में एक एंट्री के साथ। Settings → Apps इसे हटा देता है, और ling update इसे अपडेट करता है। Smart App Control बंद होना चाहिए।

ling-admin mcp · ling signal · ling chat

JetBrains, VS Code और आपका फ़ोन

आप JetBrains या VS Code को stdio MCP (ling-admin mcp) से जोड़ सकते हैं। आप अपने GB10 को Signal से (अपने ही नाम, Note to Self में), Telegram से (रिपॉज़िटरी पर काम करने वाले Mini App के साथ) और Tailscale पर Matrix से संदेश भी भेज सकते हैं। फ़ोन का हर लिंक तब तक बंद रहता है जब तक आप उसे चालू न करें। Signal एंड-टू-एंड एन्क्रिप्टेड है, और Matrix आपके अपने सर्वर पर चलता है। Telegram के संदेश बिना एन्क्रिप्शन के Telegram के सर्वरों से गुज़रते हैं, इसलिए इसे सिर्फ़ उन बातों के लिए इस्तेमाल करें जिन्हें इस तरह साझा करने में आपको आपत्ति न हो।

डॉक्स →
$ ling-admin mcp            # stdio MCP for JetBrains and VS Code
$ ling signal setup         # Note to Self only, off until linked
$ ling chat telegram setup  # topics and the Mini App

📬 Gmail, Drive, Calendar प्रीव्यू

सिर्फ़ पढ़ने के लिए, एक ऐसे साइन-इन से जो आपकी मशीन पर ही रहता है। /airgapped on से यह पूरी तरह बंद हो जाता है।

आपका कोड आपकी मेज़ पर रहता है, और आप ख़ुद जाँच सकते हैं कि ऐसा है

क्लाउड कोडिंग सहायक आपका सोर्स कोड किसी और के कंप्यूटरों पर भेजता है। Mightling उसे कहीं नहीं भेजता। मॉडल आपके GB10 पर चलता है, और Mightling में कुछ भी बाहर संपर्क नहीं करता: न इस्तेमाल की गिनती, न माप, न साइन-इन, यहाँ तक कि "गुमनाम" क्रैश रिपोर्ट भी नहीं। इसलिए आप इसे ऐसे कोड पर चला सकते हैं जिसे अपलोड करने की आपको इजाज़त नहीं, जैसे किसी ग्राहक का काम, सुरक्षित डेटा या ऐसा प्रोडक्ट जो अभी जारी नहीं हुआ।

एक कमांड Mightling का असली सेशन strace के नीचे चलाता है, जो एक ऐसा औज़ार है जो प्रोग्राम की की हुई हर कॉल पर नज़र रखता है, और फिर सेशन ने जितने नेटवर्क कनेक्शन खोले उन सबकी सूची देता है:

सब कुछ 127.0.0.1 पर ही रहा, यानी मशीन अपने आप से बात कर रही थी। एक भी DNS लुकअप नहीं हुआ (DNS लुकअप का मतलब है इंटरनेट से किसी नाम का पता पूछना)।

पक्की गारंटी चाहिए?

/airgapped on टाइप करें। तब सहायक जो भी कमांड चलाता है, उसे Linux कर्नेल से एक ख़ाली नेटवर्क मिलता है। यह मॉडल से की गई कोई विनम्र प्रार्थना नहीं है। पहुँचने के लिए बस कोई नेटवर्क ही नहीं है। साथ ही Full Access, जो सैंडबॉक्स को पार कर जाता, मना कर दिया जाता है।

SWE-bench Verified, एक DGX Spark पर मापा गया

SWE-bench Verified ओपन-सोर्स प्रोग्रामों से ली गई 500 असली समस्याओं का एक सेट है। हर समस्या में सहायक को कोड ऐसे बदलना होता है कि टेस्ट पास हो जाएँ। 2026-10-08 को हमने इनमें से 100 Mightling 1.5.1 को दीं, Qwen3.8-27B मॉडल के साथ, बिना इंटरनेट के एक DGX Spark पर। हर समस्या पर उसे अपने डिफ़ॉल्ट मोड में एक ही कोशिश मिली, और उसने 100 में से 68 हल कीं। इसे सभी 500 तक बढ़ाएँ तो हमारा अनुमान लगभग 69% है, कुछ अंकों के घट-बढ़ के साथ (95% का दायरा 63.9 से 73.4% है)। यह हमने ख़ुद नापा है, अपनी मशीन पर, समस्याओं के एक नमूने पर। यह आधिकारिक लीडरबोर्ड की प्रविष्टि नहीं है।

हम 69% का अनुमान कैसे लगाते हैं

100 समस्याएँ Verified का पाँचवाँ हिस्सा हैं, इसलिए सभी 500 का आँकड़ा एक अनुमान है। हमने इसे ऐसे बनाया। सभी 175 सार्वजनिक Verified सबमिशन के नतीजे लें, समस्या दर-समस्या। हर समस्या को एक कठिनाई और हर सिस्टम को एक क्षमता दें, एक-पैरामीटर वाले आइटम-रिस्पॉन्स (Rasch) मॉडल से। Mightling की क्षमता वह है जो इन 100 समस्याओं में 68 हल करेगी, और लगभग 69% वह है जो वही क्षमता सभी 500 पर पाएगी। प्रकाशित स्कोरों पर एक सादा रिग्रेशन एक अंक के भीतर इससे सहमत है। हमने इस तरीक़े को दूसरों पर भी जाँचा: हर सार्वजनिक सबमिशन के लिए हमने सिर्फ़ इन 100 समस्याओं पर उसका स्कोर लेकर सभी 500 पर उसका स्कोर आँका। त्रुटि 2.4 अंक रही (RMSE), और ऊपर का दायरा हर तरफ़ उसका 1.96 गुना है। तालिका का हर आँकड़ा scripts/swe_bench_compare.py से दोहराया जा सकता है, SWE-bench/experiments के सार्वजनिक समस्या-दर-समस्या डेटा से।

हमने 100 समस्याएँ Verified के प्रोग्रामों में उसी अनुपात में बाँटीं जिसमें पूरे सेट में हैं। हमने उन्हें उन समस्याओं में से चुना जिनका टेस्ट सेटअप arm64 पर चलता है और सही निकलता है (सही सुधार पास होता है, और कुछ न करना फ़ेल होता है)। प्रकाशित सिस्टम इन 100 पर सभी 500 की तुलना में 1.0 से 1.5 अंक कम पाते हैं, इसलिए यह नमूना आसान नहीं है। फिर भी यह लीडरबोर्ड की प्रविष्टि नहीं है, क्योंकि SWE-bench टीम उन्हें अपनी मशीनों पर जाँचती है।

FAQ

क्या मुझे GB10 चाहिए?

हाँ, मॉडल चलाने के लिए। आपके बाकी कंप्यूटर क्लाइंट हैं जो इसे उधार लेते हैं: Linux (Arm या x86) और macOS उसी इंस्टॉल कमांड से, और Windows (Arm या x86, प्रीव्यू) PowerShell की पंक्ति से।

मैंने Puffin इंस्टॉल किया था। क्या यह वही प्रोग्राम है?

हाँ। 1.5 में Puffin का नाम बदलकर Mightling कर दिया गया। एक बार puffin update चलाएँ, फिर आख़िरी बार puffin चलाएँ। यह आपके सेशन, सेटिंग और लिंक आगे ले जाता है, और उसके बाद कमांड ling है।

क्या सच में इसमें कुछ ख़र्च नहीं होता?

प्रोग्राम के लिए कुछ नहीं और मॉडल के लिए भी कुछ नहीं। Mightling AGPL के तहत ओपन सोर्स है, और मॉडल के वेट इस्तेमाल करने के लिए मुफ़्त हैं। आप मशीन के और उसकी बिजली के पैसे देते हैं।

मशीन के अलावा मुझे क्या चाहिए?

उसके साथ आने वाला ऑपरेटिंग सिस्टम (DGX OS 7, या Ubuntu 24.04 जहाँ NVIDIA उसे देता है), NVIDIA Container Toolkit के साथ Docker, Python 3 और Git। सादे Ubuntu पर ling-admin host check बताता है कि क्या कमी है।

क्या कुछ कभी इंटरनेट पर बाहर जाता है?

सिर्फ़ वही जो आप या सहायक माँगें, जैसे वेब सर्च (आपकी अपनी मशीन पर चलने वाले SearXNG से) और पहली बार इस्तेमाल पर डाउनलोड। /airgapped on से यह सब बंद हो जाता है।

यह कौन-सा मॉडल चलाता है?

Qwen3.8-27B, NVIDIA के 4-बिट फ़ॉर्मैट NVFP4 में, SGLang से चलता हुआ, और DFlash2 ड्राफ़्टर नाम का एक छोटा अंदाज़ा लगाने वाला सहायक साथ में। इन सबको हमने GB10 के लिए चुना और ट्यून किया। वेट लगभग 20 GB लेते हैं, और चलते समय मशीन की लगभग 38 GB मेमोरी ख़ाली रहती है।

अपना कोड अपनी डेस्क पर रखें

अगर आपको लगता है कि कोड उसी मेज़ पर रहना चाहिए जहाँ वह लिखा गया, तो GitHub पर रिपॉज़िटरी को स्टार करें। इसी तरह दूसरे GB10 मालिकों को Mightling मिलता है।

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
