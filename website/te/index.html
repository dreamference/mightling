macOS, Linux, Windows లో డెస్క్‌టాప్ యాప్, Night Shift best-of-N

Ask, Work ఒకే డెస్క్‌టాప్ విండోను పంచుకుంటాయి; రివ్యూ పేన్, వర్క్‌ట్రీలు, టెర్మినల్ ట్యాబ్‌లతో. /night add --best-of N ఒక పనిని N సార్లు నడిపి ఉత్తమ ప్రయత్నాన్ని ఉంచుకుంటుంది.

1.7.0 లో ఇంకా: Night Shift ఒక పనిని అనేక సార్లు ప్రయత్నించి ఉత్తమ ప్రయత్నాన్ని ఉంచుకోగలదు (/night add --best-of N). ఒక యంత్రం అనేక Signal వంతెనలను నడపగలదు. ఒకే నెట్‌వర్క్‌లో రెండు GB10 లను చూసే కంప్యూటర్, ఇప్పటికే తెలిసిన దాన్ని మర్చిపోకుండా వాటి మధ్య ఎంచుకోగలదు. విడుదల గమనికలు, డౌన్‌లోడ్లు.

ఇన్‌స్టాల్

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
$ ling-admin server start      # మోడల్‌ను ఒక్కసారి డౌన్‌లోడ్ చేస్తుంది (~20 GB), తర్వాత దాన్ని ప్రారంభిస్తుంది
$ cd ~/your-project && ling    # అంతే

ఇది NVIDIA DGX Spark మీద, మిగతా ప్రతి GB10 యంత్రం మీద పనిచేస్తుంది. స్క్రిప్ట్ ప్రతి డౌన్‌లోడ్‌ను విడుదల చెక్‌సమ్‌లతో సరిచూస్తుంది, ప్రతి sudo కమాండ్‌ను నడిపే ముందు మీకు చూపిస్తుంది. మీరు ముందే స్క్రిప్ట్‌ను చదవవచ్చు.

Mac, Linux క్లయింట్లు

మీ ఇతర కంప్యూటర్లు మీ ఇంటి లేదా ఆఫీసు నెట్‌వర్క్ ద్వారా GB10 మోడల్‌ను అరువు తీసుకుంటాయి. Mac లేదా మరో Linux యంత్రంలో, అదే కమాండ్ ling ను ఇన్‌స్టాల్ చేస్తుంది; మీరు టైప్ చేసే భాగం ఇదే. ఇది GB10 ను తనంతట తానే కనుగొంటుంది.

1.7.2 నుండి ఇది డెస్క్‌టాప్ యాప్‌ను కూడా Mac లో Applications లో పెడుతుంది, తెరవడానికి సిద్ధంగా. వద్దనుకుంటే --no-app జోడించండి.

Windows క్లయింట్ ప్రివ్యూ

> irm https://github.com/dreamference/mightling/releases/latest/download/install.ps1 | iex

దీన్ని PowerShell లో టైప్ చేయండి. దీనికి అడ్మినిస్ట్రేటర్ హక్కులు అవసరం లేదు (1.7.2 నుండి డెస్క్‌టాప్ యాప్‌కు కూడా ఇది వర్తిస్తుంది). తర్వాత సహాయకుడు కమాండ్లు నడిపే గోడ కట్టిన చోటును సిద్ధం చేయమని Windows ఒక్కసారి అడుగుతుంది. ఇన్‌స్టాలర్‌పై ఇంకా సంతకం లేదు, కాబట్టి Smart App Control ఆఫ్‌లో ఉండాలి. స్క్రిప్ట్ చదవండి.

ఇన్‌స్టాల్ చేయడానికి ఇతర మార్గాలు

విడుదల పేజీలో Mac డిస్క్ ఇమేజ్ (Mightling-<version>-arm64-preview.dmg, Intel కు x64), Windows ఇన్‌స్టాలర్ (Mightling-Setup-<version>-x64.exe, లేదా arm64) కూడా ఉన్నాయి. అవి సంతకం లేని ప్రివ్యూలు, కాబట్టి బ్రౌజర్‌లో డౌన్‌లోడ్ చేసినప్పుడు మీ సిస్టమ్ మొదటిసారి వాటిని ఆపుతుంది. వేటినైనా తెరిచే ముందు, విడుదలలోని సంతకం చేసిన SHA256SUMS ఫైల్‌తో సరిచూడండి.

  • macOS 15 మరియు కొత్తది: Mightling ను Applications లోకి లాగి ఒక్కసారి తెరవండి. తర్వాత System Settings › Privacy & Security కు వెళ్లి Open Anyway నొక్కండి. macOS 14 మరియు పాతదానిలో, యాప్‌ను Control నొక్కి ఉంచి క్లిక్ చేసి Open ఎంచుకోండి.
  • Windows: SmartScreen › More info › Run anyway. Smart App Control ఆఫ్‌లో ఉండాలి.

ముందు వీటిని ప్రయత్నించండి

లేదా /night add <task> తో ఈ రాత్రికి పని వదిలేయండి. మీరు నిద్రపోతున్నప్పుడు Mightling జాబితా అంతా చేస్తుంది, ప్రతి పని దాని సొంత git బ్రాంచ్‌లో; ఉదయం మీరు బ్రాంచ్‌లను పరిశీలిస్తారు.

$ ling "explain this repository to me like I'm new on the team"
# reads the code index (ling-code outline, def, refs, callers) instead of grepping,
# then walks you through the layout, the entry points and how they connect
$ ling "the tests are failing: find out why and fix them"
# runs the tests, reads the failure, edits the code and runs the tests again,
# asking before anything risky
> /night add --best-of 3 add input validation to the signup form, with tests
# tonight: three attempts, each in its own git worktree; the one the chooser picks
# is committed on its own branch, and nothing is merged or pushed
$ ling-admin night status      # the timer, the window and the queue
> /night apply <id>            # in the morning: bring the branch back as uncommitted changes

🌙 Night Shift

పడుకునే ముందు /night add <task> టైప్ చేయండి. ఉదయానికి ప్రతి పని దాని సొంత git బ్రాంచ్‌లో పూర్తవుతుంది. మీరు చేస్తే తప్ప ఏదీ మెర్జ్ కాదు, పుష్ కాదు.

మీకు ఏమి లభిస్తుంది

1.7.0 లోని డెస్క్‌టాప్ యాప్ Mightling వాడే రెండు పద్ధతులను ఒకే విండోలో ఉంచుతుంది: Ask, ఇక్కడ మీరు ప్రశ్నలు అడుగుతారు; Work, ఇక్కడ సహాయకుడు మీ కోడ్‌ను సవరిస్తాడు. Work లో పనులు టైప్ చేయడానికి ఒక పెట్టె ఉంది (ఫైళ్లు, స్కిల్స్, కమాండ్లను జత చేయవచ్చు), మార్పులను ఉంచుకునే లేదా వెనక్కి తీసుకునే ముందు చూసే ఒక పేన్, మీ కోడ్ యొక్క వేర్వేరు పని కాపీలు (వర్క్‌ట్రీలు), టెర్మినల్ ట్యాబ్‌లు, సంభాషణ పక్కనే ఒక ఫైల్ ట్రీ ఉన్నాయి. మీ ఇతర కంప్యూటర్లలో యాప్ మీ GB10 తో మాట్లాడుతుంది; దాన్ని మీ నెట్‌వర్క్‌లో కనుగొంటుంది.

Linux

తర్వాత అప్లికేషన్ మెనూ నుండి తెరవండి, లేదా ling app టైప్ చేయండి. మరింత.

Windows 11 ప్రివ్యూ

1.7.2 నుండి, PowerShell లైన్ యాప్‌ను కూడా ఇన్‌స్టాల్ చేస్తుంది: మీకు మాత్రమే, అడ్మినిస్ట్రేటర్ హక్కులు లేకుండా, Start మెనూలో ఒక ఎంట్రీతో. Settings → Apps దాన్ని తొలగిస్తుంది, ling update దాన్ని అప్‌డేట్ చేస్తుంది. Smart App Control ఆఫ్‌లో ఉండాలి.

JetBrains, VS Code మరియు మీ ఫోన్

మీరు JetBrains లేదా VS Code ను stdio MCP ద్వారా (ling-admin mcp) కనెక్ట్ చేయవచ్చు. మీ GB10 కు Signal నుండి (మీకే, Note to Self లో), Telegram నుండి (రిపోజిటరీలపై పనిచేసే Mini App తో), Tailscale మీదుగా Matrix నుండి కూడా సందేశాలు పంపవచ్చు. ప్రతి ఫోన్ లింక్ మీరు ఆన్ చేసే వరకు ఆఫ్‌లో ఉంటుంది. Signal ఎండ్-టు-ఎండ్ ఎన్‌క్రిప్ట్ చేయబడింది, Matrix మీ సొంత సర్వర్‌లో నడుస్తుంది. Telegram సందేశాలు Telegram సర్వర్ల గుండా ఎన్‌క్రిప్షన్ లేకుండా వెళ్తాయి, కాబట్టి అలా పంచుకున్నా ఇబ్బంది లేని వాటికే దాన్ని వాడండి.

📬 Gmail, Drive, Calendar ప్రివ్యూ

చదవడానికి మాత్రమే, మీ యంత్రంలోనే ఉండే సైన్-ఇన్ ద్వారా. /airgapped on తో పూర్తిగా ఆఫ్ అవుతుంది.

మీ కోడ్ మీ డెస్క్ మీదే ఉంటుంది, అది నిజమేనని మీరే సరిచూడవచ్చు

క్లౌడ్ కోడింగ్ సహాయకుడు మీ సోర్స్ కోడ్‌ను వేరొకరికి చెందిన కంప్యూటర్లకు పంపుతుంది. Mightling దాన్ని ఎక్కడికీ పంపదు. మోడల్ మీ GB10 మీద నడుస్తుంది, Mightling లో ఏదీ ఇంటికి ఫోన్ చేయదు: వాడుక లెక్కలు లేవు, కొలతలు లేవు, సైన్-ఇన్ లేదు, “అనామక” క్రాష్ రిపోర్ట్‌లు కూడా లేవు. కాబట్టి మీరు అప్‌లోడ్ చేయకూడని కోడ్ మీద దీన్ని వాడవచ్చు: క్లయింట్ పని, రక్షిత డేటా, ఇంకా విడుదల కాని ఉత్పత్తి.

ఒక కమాండ్ నిజమైన Mightling సెషన్‌ను strace కింద నడుపుతుంది (ప్రోగ్రామ్ చేసే ప్రతి కాల్‌ను గమనించే సాధనం), తర్వాత సెషన్ తెరిచిన ప్రతి నెట్‌వర్క్ కనెక్షన్‌ను జాబితా చేస్తుంది:

$ ling-admin audit egress
✔ Egress audit: pass
Network destinations:
   127.0.0.1:8000     29x  model server
   127.0.0.1:8767      1x  Gmail search service
DNS queries: none
Networked git commands: none

అంతా 127.0.0.1 లోనే ఉంది, అంటే యంత్రం తనతో తానే మాట్లాడుకోవడం. ఒక్క DNS లుకప్ కూడా లేదు (DNS లుకప్ అంటే ఒక పేరు చిరునామా ఏమిటని ఇంటర్నెట్‌ను అడగడం).

గట్టి హామీ కావాలా?

/airgapped on టైప్ చేయండి. సహాయకుడు నడిపే ప్రతి కమాండ్‌కు Linux కెర్నల్ ఖాళీ నెట్‌వర్క్ ఇస్తుంది. ఇది మోడల్‌కు మర్యాదగా చేసే అభ్యర్థన కాదు. చేరుకోవడానికి అసలు నెట్‌వర్కే ఉండదు. అదే సమయంలో, శాండ్‌బాక్స్‌ను తప్పించుకునే Full Access తిరస్కరించబడుతుంది.

ఏమి బయటికి వెళ్లవచ్చు, ఎప్పుడు

మీరు లేదా సహాయకుడు అడిగినది మాత్రమే: వెబ్ సెర్చ్ (మీ సొంత యంత్రంలో నడిచే ప్రైవేట్ SearXNG ద్వారా, అయినా సెర్చ్ మాత్రం వెబ్‌కు వెళ్తుంది), ఒక వెబ్ పేజీని తెచ్చుకోవడం, మీరు కనెక్ట్ చేసిన Google ఖాతాకు చదవడానికి మాత్రమే అభ్యర్థన, లేదా అప్‌డేట్ల తనిఖీ. /airgapped on తో వీటిలో ఏదీ జరగదు.

ఇవి GB10 మీద ఒకేసారి ఒక పనికి వేగాలు. మోడల్ స్పెక్యులేటివ్ డీకోడింగ్ అనే ఉపాయం వాడుతుంది: ఒక చిన్న సహాయకుడు కొన్ని పదాలు ముందుగా ఊహిస్తాడు, పెద్ద మోడల్ ఆ ఊహలన్నిటినీ ఒకేసారి సరిచూస్తుంది. “కోడ్ మీద పనిచేయడం” నిజమైన సహాయక సెషన్లపై కొలిచింది. కోడ్, JSON, వచనం రాయడం ఒక్కొక్కటి ఆ రకమైన అవుట్‌పుట్‌పై కొలిచారు. చివరి వరుస అది ఒకేసారి మనసులో ఉంచుకోగల వచనం: 262K టోకెన్లు, అంటే కొన్ని వందల పేజీలు. కావాలంటే నాలుగు సహాయకులను ఒకేసారి నడపండి. కోటా లేదు, “దయచేసి వేచి ఉండండి” లేదు.

✨ సెటప్ తక్కువ

  • ట్యూనింగ్ అవసరం లేదు: GB10 కోసం మోడల్‌ను, మెమరీ పరిమాణాన్ని, లో-లెవెల్ కోడ్‌ను, స్పెక్యులేటివ్ డీకోడింగ్‌ను మేమే ఎంచుకున్నాం.
  • మీ యంత్రాన్ని స్తంభింపజేయకూడదు: మోడల్‌ను లోడ్ చేసే ముందు యంత్రాన్ని తనిఖీ చేస్తుంది, లోడ్ అవుతున్నప్పుడు మెమరీని గమనిస్తుంది.
  • మీ ఇతర కంప్యూటర్లు దీన్ని కనుగొంటాయి, మీ నెట్‌వర్క్‌లో.
  • అప్‌డేట్ ఒక కమాండ్: ling update.

SWE-bench Verified అనేది ఓపెన్ సోర్స్ ప్రోగ్రామ్‌ల నుండి తీసిన 500 నిజమైన సమస్యల సమితి. ప్రతిదానికీ, పరీక్షలు పాస్ అయ్యేలా సహాయకుడు కోడ్‌ను మార్చాలి. 2026-10-08 న వాటిలో 100 ను Mightling 1.5.1 కు ఇచ్చాము, Qwen3.8-27B మోడల్‌తో, ఇంటర్నెట్ లేని ఒకే DGX Spark మీద. ప్రతిదానికీ ఒక్క ప్రయత్నం ఇచ్చాము, దాని డిఫాల్ట్ మోడ్‌లో, అది 100 లో 68 పరిష్కరించింది. దాన్ని మొత్తం 500 కు విస్తరిస్తే, సుమారు 69% అని అంచనా వేస్తున్నాము, కొన్ని పాయింట్లు అటూ ఇటూగా (95% పరిధి 63.9 నుండి 73.4%). దీన్ని మేమే, మా సొంత యంత్రం మీద, సమస్యల నమూనా మీద కొలిచాము. ఇది అధికారిక లీడర్‌బోర్డ్‌లోని ఎంట్రీ కాదు.

ఈ పట్టికను ర్యాంకింగ్‌లా కాకుండా, దగ్గరలో ఎవరున్నారో చూసే మార్గంగా చదవండి. అవే 100 సమస్యలపై, Mightling తన కంటే ఎన్నో రెట్లు పెద్ద మోడళ్లయిన Qwen3-Coder-480B, GLM-4.6 అంత సంఖ్యను పరిష్కరించింది. కానీ ప్రతి వరుస వేరే సహాయక ప్రోగ్రామ్‌ను, వేరే హార్డ్‌వేర్‌ను వాడుతుంది; లీడర్‌బోర్డ్ వరుసలు x86 కంప్యూటర్ల కోసం అధికారిక పరీక్ష ఇమేజ్‌లను వాడాయి, మావి arm64 కోసం కమ్యూనిటీ ఇమేజ్‌ల మీద నడిచాయి. refine అనే రెండవ మోడ్ కూడా ఉంది. మొదటి సెషన్ సమస్యను అధ్యయనం చేస్తుంది, ఏమీ మార్చదు; తర్వాత కొత్త సెషన్ పని చేస్తుంది. ఇది డిఫాల్ట్ కంటే ఒక సమస్య ఎక్కువ పరిష్కరించింది (69 కు 68, ప్రతి మోడ్ మరొకటి వదిలేసిన కొన్నింటిని పరిష్కరించింది), ప్రతి సమస్యకు సుమారు 2.2 రెట్లు సమయం తీసుకుంది. అందుకే మీరు ling --refine తో అడిగితే తప్ప ఇది ఆఫ్‌లో ఉంటుంది.

ఆ 69% ను మేము ఎలా అంచనా వేస్తాము

100 సమస్యలు Verified లో ఐదో వంతు, కాబట్టి మొత్తం 500 కు సంఖ్య ఒక అంచనా. మేము దాన్ని ఎలా చేశామో ఇదే. అన్ని 175 పబ్లిక్ Verified సమర్పణల ఫలితాలను సమస్య వారీగా తీసుకోండి. ఒక-పరామితి ఐటెమ్-రెస్పాన్స్ (Rasch) మోడల్‌తో ప్రతి సమస్యకు కష్టాన్ని, ప్రతి వ్యవస్థకు సామర్థ్యాన్ని ఇవ్వండి. Mightling సామర్థ్యం అంటే ఈ 100 సమస్యల్లో 68 పరిష్కరించేది; ఆ సామర్థ్యం మొత్తం 500 లో తెచ్చుకునేది సుమారు 69%. ప్రచురించిన స్కోర్లపై సాధారణ రిగ్రెషన్ ఒక పాయింట్ లోపు ఏకీభవిస్తుంది. ఇతరులపై కూడా ఈ పద్ధతిని పరీక్షించాము: ప్రతి పబ్లిక్ సమర్పణకు ఈ 100 సమస్యలపై దాని స్కోర్ మాత్రమే వాడి, మొత్తం 500 పై స్కోర్‌ను ఊహించాము. లోపం 2.4 పాయింట్లు (RMSE), పైన ఉన్న పరిధి ప్రతి వైపు దానికి 1.96 రెట్లు. పట్టికలోని ప్రతి సంఖ్యను scripts/swe_bench_compare.py తో, SWE-bench/experiments లోని పబ్లిక్ సమస్య వారీ డేటా నుండి మళ్లీ రాబట్టవచ్చు.

100 సమస్యలను Verified లోని ప్రోగ్రామ్‌ల మధ్య పూర్తి సమితిలో ఉన్న నిష్పత్తులతోనే పంచాము. వాటిని, పరీక్ష సెటప్ arm64 మీద పనిచేసి సరిచూసుకునే సమస్యల నుండి తీసుకున్నాము (సరైన పరిష్కారం పాస్ అవుతుంది, ఏమీ చేయకపోతే ఫెయిల్ అవుతుంది). ప్రచురించిన వ్యవస్థలు మొత్తం 500 కంటే ఈ 100 లో 1.0 నుండి 1.5 పాయింట్లు తక్కువ తెచ్చుకుంటాయి, కాబట్టి ఈ నమూనా సులభమైనది కాదు. అయినా ఇది లీడర్‌బోర్డ్ ఎంట్రీ కాదు, ఎందుకంటే వాటిని SWE-bench బృందం తన సొంత యంత్రాలపై గ్రేడ్ చేస్తుంది.

అవును, మోడల్‌ను నడపడానికి. మీ ఇతర కంప్యూటర్లు దాన్ని అరువు తీసుకునే క్లయింట్లు: అదే ఇన్‌స్టాల్ కమాండ్‌తో Linux (Arm లేదా x86), macOS; PowerShell లైన్తో Windows (Arm లేదా x86, ప్రివ్యూ).

నేను Puffin ఇన్‌స్టాల్ చేశాను. ఇది అదే ప్రోగ్రామా?

అవును. 1.5 లో Puffin పేరు Mightling గా మారింది. puffin update ఒకసారి నడపండి, తర్వాత puffin ను చివరిసారిగా నడపండి. ఇది మీ సెషన్లను, సెట్టింగ్‌లను, లింకులను కొత్త చోటికి తరలిస్తుంది, ఆ తర్వాత కమాండ్ ling.

నిజంగా ఏమీ ఖర్చు కాదా?

ప్రోగ్రామ్‌కు గానీ, మోడల్‌కు గానీ ఏమీ లేదు. Mightling AGPL కింద ఓపెన్ సోర్స్, మోడల్ వెయిట్లు ఉచితంగా వాడవచ్చు. మీరు యంత్రానికి, అది వాడే విద్యుత్తుకు చెల్లిస్తారు.

మెషీన్ కాకుండా నాకు ఇంకా ఏమి కావాలి?

దానితో వచ్చే ఆపరేటింగ్ సిస్టమ్ (DGX OS 7, లేదా NVIDIA అందించే చోట Ubuntu 24.04), NVIDIA Container Toolkit తో Docker, Python 3, Git. సాధారణ Ubuntu లో, ling-admin host check ఏం లేదో చెప్తుంది.

ఏదైనా ఎప్పుడైనా ఇంటర్నెట్‌కు వెళ్తుందా?

మీరు లేదా సహాయకుడు అడిగినదే, ఉదాహరణకు వెబ్ సెర్చ్ (మీ సొంత యంత్రంలో నడిచే SearXNG ద్వారా), మొదటిసారి వాడినప్పటి డౌన్‌లోడ్లు. /airgapped on తో ఇవన్నీ ఆఫ్.

ఇది ఏ మోడల్ నడుపుతుంది?

Qwen3.8-27B, NVIDIA యొక్క NVFP4 అనే 4-బిట్ ఫార్మాట్‌లో, SGLang ద్వారా, DFlash2 drafter అనే చిన్న ఊహించే సహాయకుడితో అందించబడుతుంది. వీటన్నిటినీ GB10 కోసం ఎంచుకుని ట్యూన్ చేశాము. వెయిట్లు సుమారు 20 GB తీసుకుంటాయి, అది నడుస్తున్నప్పుడు యంత్రం మెమరీలో సుమారు 38 GB ఖాళీగా ఉంటుంది.

మీ కోడ్‌ను మీ డెస్క్ మీదే ఉంచండి

కోడ్ రాసిన డెస్క్ మీదే ఉండాలని మీరు అనుకుంటే, GitHub లో రిపోజిటరీకి స్టార్ ఇవ్వండి. ఇతర GB10 యజమానులు Mightling ను అలాగే కనుగొంటారు.

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
