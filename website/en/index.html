A coding helper that runs on your own machine.
It solved about 69 of every 100 test problems.

68 of 100 real programming problems from SWE-bench Verified, solved without the internet on one DGX Spark, at about 48 tokens a second. (A token is a small piece of a word; the machine writes about 48 of them each second.) Mightling is a coding helper, a chat assistant and a desktop app, and all of it runs on your own GB10. Nothing is sent to a cloud. There is no account, no bill for each use, and no tracking. How we measured it

Install

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
$ ling-admin server start      # downloads the model once (~20 GB), then starts it
$ cd ~/your-project && ling    # that's all

This works on the NVIDIA DGX Spark and on every other GB10 machine. The script checks each download against the release's checksums, and shows you each sudo command before it runs it. You can read the script first.

Mac and Linux clients

Your other computers borrow the GB10's model over your home or office network. On a Mac or another Linux machine, the same command installs ling, the part you type into. It finds the GB10 by itself.

From 1.7.2 it also puts the desktop app in Applications on a Mac, ready to open. Add --no-app if you don't want it.

Windows client preview

> irm https://github.com/dreamference/mightling/releases/latest/download/install.ps1 | iex

Type this in PowerShell. It needs no administrator rights (from 1.7.2 that holds for the desktop app too). Windows then asks you once to set up a walled-off place where the helper runs commands. The installer is not signed yet, so Smart App Control must be off. Read the script.

Other ways to install

The release page also has the Mac disk image (Mightling-<version>-arm64-preview.dmg, or x64 for Intel) and the Windows installer (Mightling-Setup-<version>-x64.exe, or arm64). They are unsigned previews, so when you download them in a browser, your system stops them the first time. Before you open one, check it against the release's signed SHA256SUMS file.

  • macOS 15 and later: drag Mightling to Applications and open it once. Then go to System Settings › Privacy & Security and press Open Anyway. On macOS 14 and earlier, Control-click the app and choose Open.
  • Windows: SmartScreen › More info › Run anyway. Smart App Control must be off.

Try these first

Or leave work for tonight with /night add <task>. Mightling goes through the list while you sleep, each task on its own git branch, and you look over the branches in the morning.

$ ling "explain this repository to me like I'm new on the team"
# reads the code index (ling-code outline, def, refs, callers) instead of grepping,
# then walks you through the layout, the entry points and how they connect
$ ling "the tests are failing: find out why and fix them"
# runs the tests, reads the failure, edits the code and runs the tests again,
# asking before anything risky
> /night add --best-of 3 add input validation to the signup form, with tests
# tonight: three attempts, each in its own git worktree; the one the chooser picks
# is committed on its own branch, and nothing is merged or pushed
$ ling-admin night status      # the timer, the window and the queue
> /night apply <id>            # in the morning: bring the branch back as uncommitted changes

🧭 A code index

A list of where things are defined and who uses them across your project, so the helper can look code up and not search for it by guessing.

🔎 Web search and page fetch

Search goes through a private SearXNG on your own machine, so there is no search account and no key to get. The questions still go out to the web to be answered.

🌙 Night Shift

Type /night add <task> before bed. By morning each task is done on its own git branch. Nothing is merged or pushed unless you do it.

What you get

The desktop app in 1.7.0 puts both ways of using Mightling in one window: Ask, where you put questions, and Work, where the helper edits your code. Work has a box to type tasks in (you can attach files, skills and commands), a pane to look over changes before you keep or undo them, separate working copies of your code (worktrees), terminal tabs, and a file tree beside the conversation. On your other computers the app talks to your GB10, which it finds on your network.

On the GB10, the file mightling_1.7.0_arm64.deb installs the app, its menu entry and the ling-app command, along with the sandbox profile it needs. (A sandbox is a closed room for running commands, so they can't touch the rest of the machine.)

Then open it from the application menu, or type ling app. More.

Windows 11 preview

From 1.7.2, the PowerShell line installs the app too, for you alone and without administrator rights, with an entry in the Start menu. Settings → Apps removes it, and ling update updates it. Smart App Control must be off.

ling-admin mcp · ling signal · ling chat

JetBrains, VS Code, and your phone

You can connect JetBrains or VS Code through stdio MCP (ling-admin mcp). You can also send messages to your GB10 from Signal (to yourself, in Note to Self), from Telegram (with the Mini App for working on repositories), and from Matrix over Tailscale. Every phone link is off until you turn it on. Signal is end-to-end encrypted, and Matrix runs on a server of your own. Telegram messages pass through Telegram's servers unencrypted, so use it only for things you would not mind sharing that way.

Your code stays on your desk, and you can check that it does

A cloud coding helper sends your source code to computers that belong to someone else. Mightling sends it nowhere. The model runs on your GB10, and nothing in Mightling calls home: no usage counts, no measurements, no sign-in, not even "anonymous" crash reports. So you can use it on code you are not allowed to upload, such as a client's work, protected data or a product not yet released.

One command runs a real Mightling session under strace, a tool that watches every call a program makes, and then lists each network connection the session opened:

$ ling-admin audit egress
✔ Egress audit: pass
Network destinations:
   127.0.0.1:8000     29x  model server
   127.0.0.1:8767      1x  Gmail search service
DNS queries: none
Networked git commands: none

All of it stayed on 127.0.0.1, which is the machine talking to itself. There was not one DNS lookup (a DNS lookup is asking the internet for the address of a name).

Want a firm guarantee?

Type /airgapped on. Every command the helper runs then gets an empty network from the Linux kernel. That is not a polite request to the model. There is simply no network to reach. At the same time, Full Access, which would get around the sandbox, is refused.

What can leave, and when

Only what you or the helper ask for: a web search (through a private SearXNG that runs on your own machine, though the search itself still goes out to the web), a fetch of a web page, a read-only request to a Google account you have connected, or a check for updates. With /airgapped on, none of these happens.

Why Mightling

🔒 Private

The model, your code, your questions and its answers stay on the machine where they are.

  • No account, no tracking
  • An egress audit you can run again
  • /airgapped on, enforced by the kernel

⚡ Fast, and no bill

Working on code~48 tok/s
Writing code69 tok/s
JSON84 tok/s
Prose32 tok/s
Reading code~1,800 tok/s
Memory of the conversation262K

These are speeds for one task at a time on a GB10. The model uses a trick called speculative decoding: a small helper guesses several words ahead and the big model checks all the guesses in one go. "Working on code" is measured over real helper sessions. Writing code, JSON and prose are each measured on that kind of output. The last line is how much text it can hold in mind at once, 262K tokens, which is a few hundred pages. Run four helpers at once if you like. There is no quota and no "please wait".

✨ Little to set up

  • No tuning: we chose the model, the memory size, the low-level code and the speculative decoding for the GB10.
  • It should not freeze your machine: it checks the machine before loading the model, and watches memory while it loads.
  • Your other computers find it on your network.
  • An update is one command: ling update.

SWE-bench Verified, measured on one DGX Spark

SWE-bench Verified is a set of 500 real problems taken from open-source programs. For each one, the helper has to change the code so that the tests pass. On 2026-10-08 we gave 100 of them to Mightling 1.5.1, using the Qwen3.8-27B model, on one DGX Spark with no internet. It had one try at each, in its default mode, and it solved 68 of the 100. If we scale that up to all 500, we estimate about 69%, give or take a few points (the 95% range is 63.9 to 73.4%). We measured this ourselves, on our own machine, on a sample of the problems. It is not an entry on the official leaderboard.

Read this table as a way to see who is nearby, not as a ranking. On the same 100 problems, Mightling solved as many as Qwen3-Coder-480B and GLM-4.6, models many times its size. But every row uses a different helper program and different hardware, and the leaderboard rows used the official test images for x86 computers, while ours ran on community images for arm64. There is also a second mode, called refine. A first session studies the problem and changes nothing, then a fresh session does the work. It solved one more problem than the default (69 against 68, and each mode solved some problems the other missed), and it took about 2.2 times as long for each problem. So it is off unless you ask for it with ling --refine.

How we estimate the 69%

100 problems are a fifth of Verified, so the figure for all 500 is an estimate. Here is how we made it. Take the results of all 175 public Verified submissions, problem by problem. Give every problem a difficulty and every system an ability, with a one-parameter item-response (Rasch) model. Mightling's ability is the one that would solve 68 on these 100 problems, and about 69% is what that ability would score on all 500. A plain regression on the published scores agrees to within a point. We also checked the method on others: for every public submission we used only its score on these 100 problems to predict its score on all 500. The error was 2.4 points (RMSE), and the range above is 1.96 times that on each side. Every number in the table can be reproduced by scripts/swe_bench_compare.py, from the public per-problem data in SWE-bench/experiments.

We spread the 100 problems over the programs in Verified in the same proportions as the full set. We drew them from the problems whose test setup works and checks out on arm64 (the correct fix passes, and doing nothing fails). Published systems score 1.0 to 1.5 points lower on these 100 than on all 500, so the sample is not an easy one. It is still not a leaderboard entry, because the SWE-bench team grades those on their own machines.

dgxcoder · October 2026

We describe the design of Mightling Desktop, a desktop program that is open source. We give a formal list of what it can and cannot do, and we measure it. It speaks the same app-server protocol as the desktop client from the upstream vendor, keeps the same defaults as Codex, runs the model on the user's own hardware, and keeps every command in the sandbox on the workstation when the user types /airgapped on.

FAQ

Do I need a GB10?

Yes, to run the model. Your other computers are clients that borrow it: Linux (Arm or x86) and macOS with the same install command, and Windows (Arm or x86, preview) with the PowerShell line.

I installed Puffin. Is this the same program?

Yes. Puffin was renamed Mightling in 1.5. Run puffin update once, then run puffin one last time. It moves your sessions, settings and links across, and after that the command is ling.

Does it really cost nothing?

Nothing for the program or for the model. Mightling is open source under the AGPL, and the model's weights are free to use. You pay for the machine and the electricity it uses.

What do I need besides the machine?

The operating system it comes with (DGX OS 7, or Ubuntu 24.04 where NVIDIA offers it), Docker with the NVIDIA Container Toolkit, Python 3 and Git. On plain Ubuntu, ling-admin host check tells you what is missing.

Does anything ever go out to the internet?

Only what you or the helper ask for, such as a web search (through a SearXNG that runs on your own machine) and the downloads on first use. With /airgapped on, all of it is off.

Which model does it run?

Qwen3.8-27B, in NVIDIA's 4-bit format called NVFP4, served by SGLang with a small guessing helper called a DFlash2 drafter. We chose and tuned all of it for the GB10. The weights take about 20 GB, and while it runs, about 38 GB of the machine's memory stays free.

Keep your code on your desk

If you think code should stay on the desk where it was written, star the repository on GitHub. That is how other GB10 owners find Mightling.
