Também na 1.7.0: o Night Shift pode tentar uma tarefa várias vezes e ficar com a melhor tentativa (/night add --best-of N). Uma máquina pode rodar várias pontes do Signal. E um computador que enxerga dois GB10 na mesma rede pode escolher entre eles sem esquecer o que já conhece. Notas da versão e downloads.

Instalar

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
$ ling-admin server start      # baixa o modelo uma vez (~20 GB) e depois o inicia
$ cd ~/your-project && ling    # é só isso

Isto funciona no NVIDIA DGX Spark e em qualquer outra máquina GB10. O script confere cada download com as somas de verificação da versão e mostra cada comando sudo antes de executá-lo. Você pode ler o script antes.

Clientes para Mac e Linux

Seus outros computadores usam emprestado o modelo do GB10 pela rede de casa ou do escritório. Em um Mac ou em outra máquina Linux, o mesmo comando instala ling, a parte em que você digita. Ele encontra o GB10 sozinho.

A partir da 1.7.2 ele também coloca o app de desktop em Aplicativos no Mac, pronto para abrir. Acrescente --no-app se não quiser.

Cliente para Windows preview

> irm https://github.com/dreamference/mightling/releases/latest/download/install.ps1 | iex

Digite isto no PowerShell. Não precisa de direitos de administrador (a partir da 1.7.2 isso vale também para o app de desktop). Depois o Windows pede uma vez para criar um espaço isolado onde o ajudante executa comandos. O instalador ainda não é assinado, por isso o Smart App Control precisa estar desligado. Leia o script.

Outras formas de instalar

A página da versão também tem a imagem de disco para Mac (Mightling-<version>-arm64-preview.dmg, ou x64 para Intel) e o instalador do Windows (Mightling-Setup-<version>-x64.exe, ou arm64). São prévias sem assinatura; por isso, quando você as baixa pelo navegador, o sistema as bloqueia na primeira vez. Antes de abrir uma delas, confira-a com o arquivo assinado SHA256SUMS da versão.

  • macOS 15 ou mais novo: arraste o Mightling para Aplicativos e abra uma vez. Depois vá em Ajustes do Sistema › Privacidade e Segurança e clique em Abrir Mesmo Assim. No macOS 14 ou mais antigo, clique no app com a tecla Control e escolha Abrir.
  • Windows: SmartScreen › Mais informações › Executar assim mesmo. O Smart App Control precisa estar desativado.

Experimente isto primeiro

Ou deixe trabalho para esta noite com /night add <task>. O Mightling percorre a lista enquanto você dorme, cada tarefa em seu próprio branch do git, e de manhã você revisa os branches.

$ ling "explain this repository to me like I'm new on the team"
# reads the code index (ling-code outline, def, refs, callers) instead of grepping,
# then walks you through the layout, the entry points and how they connect
$ ling "the tests are failing: find out why and fix them"
# runs the tests, reads the failure, edits the code and runs the tests again,
# asking before anything risky
> /night add --best-of 3 add input validation to the signup form, with tests
# tonight: three attempts, each in its own git worktree; the one the chooser picks
# is committed on its own branch, and nothing is merged or pushed
$ ling-admin night status      # the timer, the window and the queue
> /night apply <id>            # in the morning: bring the branch back as uncommitted changes

Seu código fica na sua mesa, e você pode conferir que fica

Um ajudante de programação na nuvem envia o seu código-fonte para computadores que pertencem a outra pessoa. O Mightling não o envia a lugar nenhum. O modelo roda no seu GB10, e nada no Mightling liga para casa: sem contagem de uso, sem medições, sem login, nem mesmo relatórios de falha “anônimos”. Assim você pode usá-lo em código que não tem permissão de enviar, como o trabalho de um cliente, dados protegidos ou um produto ainda não lançado.

Um comando executa uma sessão real do Mightling sob o strace, uma ferramenta que observa cada chamada que um programa faz, e depois lista cada conexão de rede que a sessão abriu:

$ ling-admin audit egress
✔ Egress audit: pass
Network destinations:
   127.0.0.1:8000     29x  model server
   127.0.0.1:8767      1x  Gmail search service
DNS queries: none
Networked git commands: none

Tudo ficou em 127.0.0.1, que é a máquina conversando consigo mesma. Não houve nenhuma consulta DNS (uma consulta DNS é perguntar à internet qual é o endereço de um nome).

Quer uma garantia firme?

Digite /airgapped on. Cada comando que o ajudante executa passa a receber do kernel do Linux uma rede vazia. Isso não é um pedido educado ao modelo. Simplesmente não existe rede para alcançar. Ao mesmo tempo, o Full Access, que contornaria a sandbox, é recusado.

O que pode sair, e quando

Só o que você ou o ajudante pedirem: uma busca na web (por um SearXNG privado que roda na sua própria máquina, embora a busca em si ainda saia para a web), o download de uma página da web, um pedido somente de leitura a uma conta Google que você conectou, ou uma verificação de atualizações. Com /airgapped on, nada disso acontece.

Estas são velocidades para uma tarefa de cada vez em um GB10. O modelo usa um truque chamado decodificação especulativa: um ajudante pequeno adivinha várias palavras à frente e o modelo grande confere todos os palpites de uma só vez. “Trabalhando em código” é medido em sessões reais do ajudante. Escrever código, JSON e texto são medidos cada um nesse tipo de saída. A última linha é quanto texto ele consegue manter na cabeça de uma vez, 262K tokens, que são algumas centenas de páginas. Rode quatro ajudantes ao mesmo tempo, se quiser. Não há cota e não há “aguarde”.

✨ Pouco para configurar

  • Sem ajustes: escolhemos o modelo, o tamanho da memória, o código de baixo nível e a decodificação especulativa para o GB10.
  • Não deve travar a sua máquina: ele verifica a máquina antes de carregar o modelo e vigia a memória durante o carregamento.
  • Seus outros computadores o encontram na sua rede.
  • Atualizar é um comando: ling update.

SWE-bench Verified, medido em um único DGX Spark

O SWE-bench Verified é um conjunto de 500 problemas reais tirados de programas de código aberto. Em cada um, o ajudante precisa mudar o código para que os testes passem. Em 2026-10-08 demos 100 deles ao Mightling 1.5.1, com o modelo Qwen3.8-27B, em um único DGX Spark sem internet. Ele teve uma tentativa em cada um, no modo padrão, e resolveu 68 dos 100. Se estendermos isso para os 500, estimamos cerca de 69%, com uma margem de alguns pontos para mais ou para menos (a faixa de 95% vai de 63,9 a 73,4%). Medimos isso nós mesmos, na nossa própria máquina, em uma amostra dos problemas. Não é uma entrada no leaderboard oficial.

Leia esta tabela como um jeito de ver quem está por perto, não como um ranking. Nos mesmos 100 problemas, o Mightling resolveu tantos quanto o Qwen3-Coder-480B e o GLM-4.6, modelos muitas vezes maiores. Mas cada linha usa um programa ajudante diferente e um hardware diferente, e as linhas do leaderboard usaram as imagens de teste oficiais para computadores x86, enquanto as nossas rodaram em imagens da comunidade para arm64. Existe também um segundo modo, chamado refine. Uma primeira sessão estuda o problema e não muda nada; depois uma sessão nova faz o trabalho. Ele resolveu um problema a mais que o modo padrão (69 contra 68, e cada modo resolveu alguns problemas que o outro perdeu), e levou cerca de 2,2 vezes mais tempo por problema. Por isso fica desligado, a menos que você peça com ling --refine.

Como estimamos os 69%

100 problemas são um quinto do Verified, então o número para os 500 é uma estimativa. Veja como a fizemos. Pegamos os resultados de todas as 175 submissões públicas do Verified, problema por problema. Damos a cada problema uma dificuldade e a cada sistema uma habilidade, com um modelo de resposta ao item de um parâmetro (Rasch). A habilidade do Mightling é aquela que resolveria 68 nestes 100 problemas, e cerca de 69% é o que essa habilidade alcançaria nos 500. Uma regressão simples sobre as notas publicadas concorda com diferença de até um ponto. Também testamos o método nos outros: para cada submissão pública, usamos só a nota nestes 100 problemas para prever a nota nos 500. O erro foi de 2,4 pontos (RMSE), e a faixa acima é 1,96 vez isso para cada lado. Todos os números da tabela podem ser reproduzidos por scripts/swe_bench_compare.py, a partir dos dados públicos por problema em SWE-bench/experiments.

Distribuímos os 100 problemas entre os programas do Verified nas mesmas proporções do conjunto completo. Tiramos os problemas de entre aqueles cujo ambiente de teste funciona e se confirma em arm64 (a correção certa passa, e não fazer nada falha). Os sistemas publicados tiram 1,0 a 1,5 ponto a menos nestes 100 do que nos 500, então a amostra não é fácil. Mesmo assim, não é uma entrada no leaderboard, porque a equipe do SWE-bench as avalia nas máquinas dela.

FAQ

Preciso de um GB10?

Sim, para rodar o modelo. Os seus outros computadores são clientes que o usam emprestado: Linux (Arm ou x86) e macOS com o mesmo comando de instalação, e Windows (Arm ou x86, prévia) com a linha do PowerShell.

Instalei o Puffin. É o mesmo programa?

Sim. O Puffin foi renomeado para Mightling na 1.5. Execute puffin update uma vez e depois execute puffin mais uma última vez. Ele leva suas sessões, configurações e links para o novo lugar, e depois disso o comando é ling.

Custa mesmo nada?

Nada pelo programa nem pelo modelo. O Mightling é de código aberto sob a AGPL, e os pesos do modelo são livres para usar. Você paga pela máquina e pela eletricidade que ela gasta.

O que preciso além da máquina?

O sistema operacional que vem com ela (DGX OS 7, ou Ubuntu 24.04 onde a NVIDIA o oferece), Docker com o NVIDIA Container Toolkit, Python 3 e Git. Em um Ubuntu comum, ling-admin host check diz o que está faltando.

Alguma coisa sai para a internet?

Só o que você ou o ajudante pedirem, como uma busca na web (por um SearXNG que roda na sua própria máquina) e os downloads do primeiro uso. Com /airgapped on, tudo isso fica desligado.

Qual modelo ele roda?

Qwen3.8-27B, no formato de 4 bits da NVIDIA chamado NVFP4, servido pelo SGLang com um pequeno ajudante de palpites chamado drafter DFlash2. Escolhemos e ajustamos tudo para o GB10. Os pesos ocupam cerca de 20 GB e, enquanto ele roda, cerca de 38 GB da memória da máquina continuam livres.

Mantenha seu código na sua mesa

Se você acha que o código deve ficar na mesa onde foi escrito, dê uma estrela ao repositório no GitHub. É assim que outros donos de GB10 encontram o Mightling.

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
