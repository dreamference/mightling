Instalar

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
$ ling-admin server start      # baixa o modelo uma única vez (~20 GB) e depois o serve
$ cd ~/your-project && ling    # só isso

Funciona no NVIDIA DGX Spark e em toda máquina GB10. O script confere cada download com os checksums da versão e mostra cada comando sudo antes de executá-lo. Leia-o antes, se quiser.

Clientes para Mac e Linux

Seus outros computadores usam o modelo do GB10 pela rede local. Em um Mac ou em outra máquina Linux, o mesmo comando acima instala o cliente ling, que encontra o GB10 sozinho.

A partir da 1.7.2, ele também coloca o app de desktop em Aplicativos no Mac, pronto para abrir (--no-app o deixa de fora).

Cliente para Windows preview

> irm https://github.com/dreamference/mightling/releases/latest/download/install.ps1 | iex

No PowerShell. Instala sem direitos de administrador (a partir da 1.7.2, o app de desktop também) e depois o Windows pede uma vez para configurar o sandbox do agente. Ainda sem assinatura, então o Smart App Control precisa estar desativado. Leia o script.

Outras formas de instalar

A página da versão traz também o dmg para Mac (Mightling-<version>-arm64-preview.dmg, ou x64 para Intel) e o instalador do Windows (Mightling-Setup-<version>-x64.exe, ou arm64). São previews sem assinatura: baixados pelo navegador, são bloqueados na primeira vez. Confira cada um com o SHA256SUMS assinado da versão antes.

  • macOS 15 e posterior: arraste o Mightling para Aplicativos e abra-o uma vez; depois, Ajustes do Sistema › Privacidade e Segurança › Abrir Mesmo Assim. No macOS 14 e anteriores, Control-clique no app › Abrir.
  • Windows: SmartScreen › Mais informações › Executar assim mesmo. O Smart App Control precisa estar desativado.

Experimente isto primeiro

Ou deixe trabalho na fila para esta noite com /night add <task>: o Mightling percorre a fila enquanto você dorme, cada tarefa em seu próprio branch do git, e você revisa os branches com o café.

$ ling "explain this repository to me like I'm new on the team"
# reads the code index (ling-code outline, def, refs, callers) instead of grepping,
# then walks you through the layout, the entry points and how they connect
$ ling "the tests are failing: find out why and fix them"
# runs the tests, reads the failure, edits the code and runs the tests again,
# asking before anything risky
> /night add --best-of 3 add input validation to the signup form, with tests
# tonight: three attempts, each in its own git worktree; the one the chooser picks
# is committed on its own branch, and nothing is merged or pushed
$ ling-admin night status      # the timer, the window and the queue
> /night apply <id>            # in the morning: bring the branch back as uncommitted changes

Definições, chamadores e impacto em todo o seu repositório, para o agente encontrar o código em vez de procurá-lo com grep.

/night add <task> antes de dormir; de manhã, cada tarefa feita em seu próprio branch do git. Nada é mesclado nem enviado sem você.

Seu código não sai da sua mesa — e você pode provar

Agentes de programação na nuvem enviam seu código-fonte para os servidores de outra empresa. O Mightling não o envia para lugar nenhum: o modelo roda no seu GB10 e nada no Mightling liga para casa. Sem análise de uso, sem métricas, sem login, sem relatórios de falha “anônimos”. Isso o torna utilizável com código que você não pode enviar: trabalho de clientes, dados regulados, produtos não lançados.

Um comando roda uma sessão real do Mightling sob o strace e lista cada conexão de rede que ela fez:

$ ling-admin audit egress
✔ Egress audit: pass
Network destinations:
   127.0.0.1:8000     29x  model server
   127.0.0.1:8767      1x  Gmail search service
DNS queries: none
Networked git commands: none

Tudo ficou em 127.0.0.1. Nenhuma consulta DNS.

Precisa de uma garantia firme?

Digite /airgapped on e cada comando que o agente executa recebe do kernel do Linux um namespace de rede vazio. Não é um pedido educado ao modelo: simplesmente não há rede para alcançar. O Full Access, que contornaria o sandbox, é recusado ao mesmo tempo.

O que pode sair, e quando

Só o que você ou o agente pedirem: uma busca na web (por um SearXNG privado na sua própria máquina), o download de uma página, uma requisição somente leitura a uma conta Google que você conectou, ou uma verificação de atualização. Com /airgapped on, nada disso.

SWE-bench Verified, medido em um único DGX Spark

Em 2026-10-08, o agente do Mightling 1.5.1 com Qwen3.8-27B resolveu 68 de 100 tarefas do SWE-bench Verified em um único DGX Spark, offline: uma amostra fixa de 100 tarefas, uma tentativa por tarefa, modo padrão. Extrapolado para as 500 tarefas, são ≈69% estimados (faixa de 95%: 63,9–73,4%). É uma medição nossa, na nossa máquina e sobre um subconjunto, não uma entrada do leaderboard.

Leia como uma referência, não como um ranking. Nas mesmas 100 tarefas, o Mightling resolveu tantas quanto o Qwen3-Coder-480B e o GLM-4.6, modelos muitas vezes maiores, mas cada linha usa um agente diferente, um hardware diferente e, nas linhas do leaderboard, as imagens de teste x86 oficiais, enquanto as nossas rodaram em imagens arm64 da comunidade. No modo refine, uma primeira sessão estuda a tarefa sem mudar nada e uma sessão nova a executa: ele resolveu uma tarefa a mais que o modo padrão (69 contra 68, cada modo ganhando tarefas que o outro perdeu), em cerca de 2,2 vezes o tempo por tarefa, então continua opcional (ling --refine).

Como o ≈69% é estimado

100 tarefas são um quinto do Verified, então o número do conjunto completo é uma estimativa. Ajusta-se um modelo de resposta ao item de um parâmetro (Rasch) aos resultados por tarefa de todas as 175 submissões públicas do Verified: cada tarefa recebe uma dificuldade e cada sistema uma habilidade. A habilidade do Mightling é a que explica 68 tarefas resolvidas nestas 100; ≈69% é a pontuação esperada dessa habilidade nas 500 (uma regressão simples sobre as pontuações publicadas concorda com diferença de um ponto). Para verificar, cada submissão pública foi pontuada só nestas 100 tarefas e sua pontuação geral foi prevista do mesmo modo: o erro foi de 2,4 pontos (RMSE), e a faixa acima é ±1,96 vezes isso. Todo número da tabela é reproduzido por scripts/swe_bench_compare.py a partir dos dados públicos por tarefa de SWE-bench/experiments.

As 100 tarefas se distribuem pelos repositórios do Verified na proporção do conjunto completo, entre as tarefas cujo ambiente de teste roda e valida em arm64 (o patch de referência passa, uma mudança vazia falha). Os sistemas publicados pontuam de 1,0 a 1,5 ponto menos nestas 100 do que nas 500, então a amostra não é fácil. Não é uma entrada do leaderboard: essas são avaliadas pela equipe do SWE-bench na própria infraestrutura.

  1. Mightling: 100 tarefas, uma tentativa cada; um DGX Spark (GB10, 128 GB), modelo servido localmente, sem nuvem; modo padrão medido em 2026-10-08, modo refine em 2026-10-09. Estimativa a partir dos dados por tarefa do SWE-bench experiments.

FAQ

Preciso de um GB10?

Sim, para rodar o modelo. Seus outros computadores o usam como clientes: Linux (Arm ou x86) e macOS com o mesmo comando de instalação, Windows (Arm ou x86, preview) com a linha do PowerShell.

Instalei o Puffin. É este mesmo?

Sim: o Puffin foi renomeado para Mightling na 1.5. Rode puffin update uma vez e depois puffin uma última vez. Ele move suas sessões, configurações e links, e daí em diante o comando é ling.

É grátis de verdade?

Sim. O Mightling é código aberto sob a AGPL, e os pesos do modelo são gratuitos. Seu único custo de operação é a eletricidade.

O que preciso além da máquina?

O sistema operacional que ela traz (DGX OS 7, ou Ubuntu 24.04 onde o fabricante o oferece), Docker com o NVIDIA Container Toolkit, Python 3 e Git. Em um Ubuntu comum, ling-admin host check diz o que está faltando.

Alguma coisa chega à internet?

Só o que você ou o agente pedirem, como uma busca na web por um SearXNG na sua própria máquina, e os downloads da primeira vez. /airgapped on desliga tudo isso.

Qual modelo ele roda?

Qwen3.8-27B no formato NVFP4 de 4 bits da NVIDIA, servido pelo SGLang com um drafter DFlash2, escolhido e ajustado para o GB10. Cerca de 20 GB de pesos; aproximadamente 38 GB da memória da máquina continuam livres enquanto ele serve.
