v1.7.1 →
v1.7.02026-10-20

macOS、Linux、Windows のデスクトップアプリと、Night Shift の best-of-N

Ask と Work は1つのデスクトップウィンドウを共有し、見直しのパネル、worktree、ターミナルのタブもあります。/night add --best-of N は、作業を N 回実行して、いちばんよい結果を残します。

v1.7.0 →

1.7.0 では、ほかにもあります。Night Shift は、1つの作業を何回か試して、いちばんよい結果を残せます（/night add --best-of N）。1台のマシンで、複数の Signal ブリッジを動かせます。また、同じネットワークに GB10 が2台あるコンピュータは、すでに知っているほうを忘れずに、どちらかを選べます。リリースノートとダウンロード。

インストール

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
$ ling-admin server start      # モデルを1回だけダウンロード（約20 GB）して、起動します
$ cd ~/your-project && ling    # これだけです

NVIDIA DGX Spark でも、ほかの GB10 のマシンでも動きます。スクリプトは、ダウンロードしたものをリリースのチェックサムと照らし合わせ、sudo のコマンドは実行する前にひとつずつ見せます。先にスクリプトを読むこともできます。

Mac と Linux のクライアント

ほかのコンピュータは、家やオフィスのネットワーク越しに GB10 のモデルを借ります。Mac やほかの Linux マシンでは、同じコマンドで、入力する側の ling が入ります。GB10 は自動で見つかります。

1.7.2 からは、Mac ではデスクトップアプリも「アプリケーション」に入り、すぐ開けます。いらないときは --no-app を付けてください。

Windows クライアント プレビュー

> irm https://github.com/dreamference/mightling/releases/latest/download/install.ps1 | iex

PowerShell でこれを入力します。管理者権限はいりません（1.7.2 からはデスクトップアプリも同じです）。そのあと Windows が、アシスタントがコマンドを動かす、壁で囲まれた場所を用意するかどうか、1回だけ聞いてきます。インストーラーにはまだ署名がないので、Smart App Control はオフにしておく必要があります。スクリプトを読む。

そのほかのインストール方法

リリースのページには、Mac のディスクイメージ（Mightling-<version>-arm64-preview.dmg。Intel 用は x64）と、Windows のインストーラー（Mightling-Setup-<version>-x64.exe。arm64 用もあります）もあります。どちらも署名のない試用版なので、ブラウザでダウンロードすると、最初はシステムに止められます。開く前に、リリースの署名つき SHA256SUMS ファイルと照らし合わせてください。

  • macOS 15 以降：Mightling を「アプリケーション」にドラッグして、1回開きます。次に「システム設定 › プライバシーとセキュリティ」へ行き、このまま開く（Open Anyway）を押します。macOS 14 以前では、アプリを Control キーを押しながらクリックして、「開く」を選びます。
  • Windows:SmartScreen › 詳細情報 › 実行。スマート アプリ コントロール（Smart App Control）はオフにしておく必要があります。

まずはこれを試してみてください

または、/night add <task> で、今夜の分の仕事を残していきます。眠っているあいだに Mightling がリストを順に進め、作業ごとに別々の git ブランチを使います。朝になったら、そのブランチを見直します。

$ ling "explain this repository to me like I'm new on the team"
# reads the code index (ling-code outline, def, refs, callers) instead of grepping,
# then walks you through the layout, the entry points and how they connect
$ ling "the tests are failing: find out why and fix them"
# runs the tests, reads the failure, edits the code and runs the tests again,
# asking before anything risky
> /night add --best-of 3 add input validation to the signup form, with tests
# tonight: three attempts, each in its own git worktree; the one the chooser picks
# is committed on its own branch, and nothing is merged or pushed
$ ling-admin night status      # the timer, the window and the queue
> /night apply <id>            # in the morning: bring the branch back as uncommitted changes

できること

1.7.0 のデスクトップアプリは、Mightling の2つの使い方を1つのウィンドウにまとめました。質問をする Ask と、アシスタントがコードを直す Work です。Work には、作業を入力する欄（ファイル、スキル、コマンドを添えられます）、変更を残すか取り消すかを決める前に見直すパネル、コードの別々の作業用コピー（worktree）、ターミナルのタブ、会話の横のファイルツリーがあります。ほかのコンピュータでは、アプリがネットワーク上の GB10 を見つけて、そこと話します。

🪟 デスクトップアプリ プレビュー

Ask と Work を1つのウィンドウで。GB10、Mac、Linux、Windows で使えます。アシスタントのセッションは、あなたの承認を求めます。変更を見直すパネル、別々の作業用コピー、取り消しもあります。1.7 の新機能。

ウェブ検索、画像検索、入力の代わりに話しかける質問と、アシスタントのセッションも、このマシンから、またはペアリングした携帯電話から使えます。どれもあなたのマシンの同じモデルを使います。

JetBrains、VS Code、そしてスマートフォン

JetBrains や VS Code は、stdio MCP（ling-admin mcp）でつなげます。GB10 には、Signal（自分あて、Note to Self）、Telegram（リポジトリを扱う Mini App つき）、Tailscale 上の Matrix からメッセージを送ることもできます。携帯電話とのつながりは、どれもあなたがオンにするまでオフです。Signal はエンドツーエンドで暗号化され、Matrix はあなた自身のサーバーで動きます。Telegram のメッセージは暗号化されないまま Telegram のサーバーを通るので、そうして共有しても困らないことだけに使ってください。

$ ling chat telegram setup  # topics and the Mini App

読み取り専用で、サインインの情報はあなたのマシンの中にとどまります。/airgapped on で完全にオフになります。

コードはあなたの机の上にあり、それを自分で確かめられます

クラウドのコーディング・アシスタントは、あなたのソースコードをほかの人のコンピュータに送ります。Mightling は、どこにも送りません。モデルはあなたの GB10 の上で動き、Mightling の中に外へ連絡するものはありません。利用回数の集計も、計測も、サインインも、「匿名」のクラッシュ報告さえありません。ですから、アップロードしてはいけないコードにも使えます。お客さまの仕事、守るべきデータ、まだ出していない製品などです。

コマンドを1つ実行すると、本物の Mightling のセッションが strace（プログラムの行うすべての呼び出しを見張る道具）の下で動き、そのセッションが開いたネットワーク接続を1つずつ一覧にします。

$ ling-admin audit egress
✔ Egress audit: pass
Network destinations:
   127.0.0.1:8000     29x  model server
   127.0.0.1:8767      1x  Gmail search service
DNS queries: none
Networked git commands: none

すべて 127.0.0.1、つまりマシンが自分自身と話しているだけでした。DNS の問い合わせ（DNS の問い合わせとは、名前のアドレスをインターネットに尋ねること）は、1つもありませんでした。

確実な保証がほしいですか？

/airgapped on と入力します。すると、アシスタントが動かすコマンドはどれも、Linux のカーネルから空のネットワークを渡されます。これはモデルへのお願いではありません。つながる先のネットワークが、そもそもないのです。同時に、サンドボックスを回避できてしまう Full Access は、断られます。

外に出るもの、そのタイミング

あなたかアシスタントが頼んだものだけです。ウェブ検索（あなた自身のマシンで動く専用の SearXNG を通しますが、検索そのものはウェブへ出ていきます）、ウェブページの取得、つないだ Google アカウントへの読み取り専用の要求、更新の確認です。/airgapped on にすると、どれも起こりません。

Mightling を選ぶ理由

🔒 プライベート

モデルも、あなたのコードも、質問も、その答えも、そのマシンの中にとどまります。

  • アカウントなし、追跡なし
  • 何度でもやり直せる egress 監査
  • /airgapped on はカーネルが強制

⚡ 速くて、料金なし

コードの作業中~48 tok/s
コードを書く69 tok/s
JSON84 tok/s
文章32 tok/s
コードの読み込み~1,800 tok/s
会話の記憶262K

これは GB10 で1回に1つの作業をしたときの速さです。モデルは、推測デコード（speculative decoding）という工夫を使います。小さな助手が先の言葉をいくつか予想し、大きなモデルがその予想を一度にまとめて確かめます。「コードの作業中」は、本物のアシスタントのセッションで測っています。コード、JSON、文章を書く速さは、それぞれその種類の出力で測っています。いちばん下の行は、一度に覚えていられる文章の量で、262K トークン、つまり数百ページ分です。アシスタントを同時に4つ動かしても構いません。上限も、「しばらくお待ちください」もありません。

✨ 設定はほとんどなし

  • 調整は不要：モデル、メモリの大きさ、低レベルのコード、推測デコードを、GB10 向けに私たちが選びました。
  • マシンを固まらせないように：モデルを読み込む前にマシンを調べ、読み込み中はメモリを見張ります。
  • ほかのコンピュータが見つけます。同じネットワークの中で見つかります。
  • 更新はコマンド1つ：ling update。

SWE-bench Verified、DGX Spark 1 台での実測

SWE-bench Verified は、オープンソースのプログラムから取った、実際の問題500問のセットです。アシスタントは、それぞれの問題で、テストが通るようにコードを直さなければなりません。2026-10-08 に、そのうち100問を Mightling 1.5.1 に出しました。モデルは Qwen3.8-27B、マシンはインターネットなしの DGX Spark 1台です。どの問題も、標準のモードで1回だけ挑戦し、100問のうち68問を解きました。500問全部に広げると、約69%と見積もっています。前後に数ポイントの幅があります（95%の範囲は63.9〜73.4%）。これは私たち自身が、私たちのマシンで、問題の一部を使って測ったものです。公式のリーダーボードへの登録ではありません。

69%をどう見積もったか

100問は Verified の5分の1なので、500問全部の数字は見積もりです。やり方は次のとおりです。公開されている Verified の175件の提出すべてについて、問題ごとの結果を集めます。1パラメータの項目反応（Rasch）モデルで、どの問題にも難しさを、どのシステムにも実力をつけます。Mightling の実力は、この100問で68問を解く実力で、その実力が500問全部で取る点が約69%です。公表されている点数への単純な回帰でも、1ポイント以内で一致します。方法そのものも、ほかのシステムで確かめました。公開されている提出それぞれについて、この100問の点数だけから500問全部の点数を予想したのです。誤差は2.4ポイント（RMSE）で、上の範囲はその1.96倍を前後につけたものです。表の数字はすべて、scripts/swe_bench_compare.py で、SWE-bench/experiments の公開されている問題ごとのデータから再現できます。

100問は、Verified の中のプログラムごとの割合が、全体と同じになるように選びました。選んだのは、テストの準備が arm64 で動き、確かめられている問題です（正しい修正は通り、何もしなければ失敗します）。公表されているシステムは、500問全部より、この100問のほうが1.0〜1.5ポイント低い点になります。つまり、やさしい問題を選んだわけではありません。それでも、リーダーボードへの登録ではありません。SWE-bench のチームは、自分たちのマシンで採点するからです。

  1. Mightling：100問、各1回の挑戦。DGX Spark 1台（GB10、128 GB）。モデルはマシンの上で動かし、クラウドは使いません。標準モードは2026-10-08、refine モードは2026-10-09に測定。見積もりには、SWE-bench experiments の問題ごとのデータを使っています。
  2. 500 タスク、1 回の試行。ハードウェアは不明。出典：experiments, 20250805_openhands-Qwen3-Coder-480B-A35B-Instruct。同じモデルを mini-SWE-agent で使った場合：57/100、55.4%。
  3. 500 タスク、1 回の試行。エージェントは非公開、ハードウェアは不明。出典：experiments, 20250930_zai_glm4-6。
  4. 500 タスク、1 回の試行。ハードウェアは不明。出典：experiments, 20260217_mini-v2.0.0_kimi-k2-5-high。
  5. 500 タスク、1 回の試行。ハードウェアは不明。出典：experiments, 20260217_mini-v2.0.0_deepseek-3-2-high。
  6. いずれも 500 タスク。ハードウェアは不明。4 件の提出：OpenHands(80/100、77.6%)、live-SWE-agent(80/100、79.2%)、Sonar Foundation Agent(77/100、79.2%)、mini-SWE-agent, high（79/100、76.8%）。これより前の mini-SWE-agent の実行は 74/100、74.4% でした。
  7. 500 タスク、1 回の試行。ハードウェアは不明。出典：experiments, 20251120_livesweagent_gemini-3-pro-preview。同じモデルを mini-SWE-agent で使った場合：72/100、74.2%。
  8. リーダーボードで公表されている 20–40B モデルの最高成績。500 タスク。テスト時スケーリングは 1 タスクにつき 2 回以上試行。ハードウェアは不明。出典：テスト時スケーリング、1 回の試行。
  9. 500 タスク、1 回の試行。ハードウェアは不明。出典：experiments, 20251209_mini-v1.17.2_devstral-small-2512。
  10. GitHub 自身の数値（2025 年 4 月）:「agent mode achieves a pass rate of 56.0% on SWE-bench Verified with Claude 3.7 Sonnet」。タスク数、試行回数、ハードウェアは不明で、リーダーボードには載っていません。出典：GitHub ブログ。
  11. Anthropic は Claude モデルの SWE-bench Verified の結果を、独自のシンプルなスキャフォールド（bash ツールと編集ツール）で測って公表しており、Claude Code という製品としては公表していません。出典：Claude Code、Anthropic の SWE-bench の手法。
  12. Cursor が公表しているのは自社のベンチマーク Cursor Bench の結果で、SWE-bench Verified ではありません。出典：Cursor ブログ、Composer。

FAQ

GB10 は必須ですか？

はい、モデルを動かすためです。ほかのコンピュータは、それを借りるクライアントです。Linux（Arm または x86）と macOS は同じインストールのコマンドで、Windows（Arm または x86、試用版）はPowerShell の1行で使えます。

Puffin を入れました。これは同じプログラムですか？

はい。Puffin は1.5で Mightling に名前が変わりました。puffin update を1回実行し、そのあと最後にもう1回 puffin を実行してください。セッション、設定、リンクが新しい側に移り、それからはコマンドが ling になります。

本当に無料ですか？

プログラムもモデルも無料です。Mightling は AGPL のオープンソースで、モデルの重みも自由に使えます。かかるのは、マシンと、その電気代だけです。

マシン以外に必要なものは？

付属のオペレーティングシステム（DGX OS 7。NVIDIA が用意している場合は Ubuntu 24.04）、NVIDIA Container Toolkit つきの Docker、Python 3、Git です。ふつうの Ubuntu では、ling-admin host check が足りないものを教えます。

インターネットに出ていくものはありますか？

あなたかアシスタントが頼んだものだけです。たとえばウェブ検索（あなた自身のマシンで動く SearXNG を通します）と、最初に使うときのダウンロードです。/airgapped on にすると、すべてオフになります。

どのモデルが動きますか？

Qwen3.8-27B を、NVIDIA の4ビット形式 NVFP4 で、SGLang が動かしています。DFlash2 ドラフターという小さな推測の助手もつきます。どれも GB10 向けに私たちが選び、調整しました。重みは約20 GB で、動いているあいだも、マシンのメモリは約38 GB 空いたままです。

コードは手元に置いておこう

コードは、書かれた机の上にとどまるべきだと思うなら、GitHub でリポジトリにスターをつけてください。ほかの GB10 の持ち主が Mightling を見つけるきっかけになります。

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
