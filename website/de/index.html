Schnelles KI-Coding auf deinem Schreibtisch.
Rund 69 % auf SWE‑bench Verified.

68 von 100 SWE-bench-Verified-Aufgaben, offline auf einem DGX Spark gelöst, mit rund 47 Tokens pro Sekunde. Ein Coding-Agent, ein Chat-Assistent und eine Desktop-App, die komplett auf deinem eigenen GB10 laufen. Keine Cloud. Kein Konto. Keine API-Rechnung. Keine Telemetrie. So wurde gemessen

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
$ ling-admin server start      # lädt das Modell einmalig herunter (~20 GB) und stellt es bereit
$ cd ~/your-project && ling    # das war's

Läuft auf dem NVIDIA DGX Spark und jedem GB10-Rechner. Das Skript prüft jeden Download gegen die Prüfsummen des Releases und zeigt jeden sudo-Befehl an, bevor es ihn ausführt. Lies es vorher durch, wenn du magst.

Mac- und Linux-Clients

Deine anderen Rechner nutzen das Modell des GB10 über das lokale Netzwerk. Auf einem Mac oder einem anderen Linux-Rechner installiert derselbe Befehl von oben den Client ling; er findet den GB10 von selbst.

Ab 1.7.2 legt er auf dem Mac auch die Desktop-App in Programme, startbereit (--no-app lässt sie weg).

Neu in 1.7: die Desktop-App für Mac, Linux und Windows

Die Desktop-App von Mightling 1.7.0 vereint Ask und Work in einem Fenster. Work ist eine vollständige Werkbank für Agentensitzungen: ein Eingabefeld mit Dateien, Skills und Befehlen, ein Review-Bereich zum Stagen, Zurücksetzen und Committen, Worktrees, Terminal-Tabs sowie Dateibaum und Datei-Tabs neben dem Thread. Auf deinen anderen Rechnern ist sie ein Client deines GB10, den sie im lokalen Netzwerk findet.

macOS Vorschau

Ab 1.7.2 legt der Installationsbefehl Mightling neben ling in Programme, und es öffnet sich wie jede andere App. Apple Silicon und Intel, ab macOS 12. ling update aktualisiert es.

Linux

Auf dem GB10 installiert mightling_1.7.0_arm64.deb die App, ihren Starter-Eintrag und den Befehl ling-app, samt dem Sandbox-Profil, das sie braucht:

$ sudo apt install ./mightling_1.7.0_arm64.deb

Öffne sie dann über das Anwendungsmenü oder mit ling app. Mehr.

Windows 11 Vorschau

Ab 1.7.2 installiert die PowerShell-Zeile auch die App, nur für dich und ohne Administratorrechte, mit Eintrag im Startmenü; unter Einstellungen → Apps wird sie wieder entfernt; ling update aktualisiert sie. Die intelligente App-Steuerung muss ausgeschaltet sein.

Weitere Installationswege

Auf der Release-Seite liegen außerdem das Mac-dmg (Mightling-<version>-arm64-preview.dmg, für Intel x64) und der Windows-Installer (Mightling-Setup-<version>-x64.exe, oder arm64). Es sind unsignierte Vorschauen: Im Browser heruntergeladen, werden sie beim ersten Mal blockiert. Prüfe jede Datei vorher gegen die signierte SHA256SUMS des Releases.

  • macOS 15 und neuer: Ziehe Mightling in Programme und öffne es einmal, dann Systemeinstellungen › Datenschutz & Sicherheit › Trotzdem öffnen. Unter macOS 14 und älter: App mit gedrückter Control-Taste anklicken › Öffnen.
  • Windows: SmartScreen › Weitere Informationen › Trotzdem ausführen. Die intelligente App-Steuerung muss ausgeschaltet sein.

Ebenfalls in 1.7.0: Night Shift kann eine Aufgabe mehrmals versuchen und den besten Versuch behalten (/night add --best-of N), eine Maschine kann mehrere Signal-Bridges betreiben, und ein Client wählt zwischen zwei Nodes im selben Netzwerk, ohne den ihm bekannten zu verlieren. SWE-bench Verified, gemessen auf einem DGX Spark

Am 2026-10-08 löste der Agent von Mightling 1.5.1 mit Qwen3.8-27B 68 von 100 SWE-bench-Verified-Aufgaben auf einem DGX Spark, offline: eine feste Stichprobe von 100 Aufgaben, ein Versuch pro Aufgabe, Standardmodus. Hochgerechnet auf alle 500 Aufgaben sind das geschätzt ≈69 % (95-%-Band 63,9–73,4 %). Das ist unsere eigene Messung, auf unserer eigenen Maschine und an einer Teilmenge, kein Leaderboard-Eintrag.

Versteh das als Einordnung, nicht als Rangliste. Auf denselben 100 Aufgaben löste Mightling so viele wie Qwen3-Coder-480B und GLM-4.6, Modelle, die um ein Vielfaches größer sind. Aber jede Zeile nutzt einen anderen Agenten, andere Hardware und, bei den Leaderboard-Zeilen, die offiziellen x86-Testimages, während unsere auf Community-arm64-Images liefen. Im Refine-Modus untersucht eine erste Sitzung die Aufgabe, ohne etwas zu ändern, und eine frische Sitzung setzt sie um: Er löste eine Aufgabe mehr als der Standardmodus (69 gegen 68, wobei jede Variante Aufgaben gewann, die die andere verlor), bei etwa dem 2,2-Fachen der Zeit pro Aufgabe, und bleibt deshalb optional (ling --refine).

Wie die ≈69 % geschätzt werden

100 Aufgaben sind ein Fünftel von Verified, die Zahl für das ganze Set ist also eine Schätzung. Ein Item-Response-Modell mit einem Parameter (Rasch) wird an die Ergebnisse pro Aufgabe aller 175 öffentlichen Verified-Einreichungen angepasst: Jede Aufgabe erhält eine Schwierigkeit, jedes System eine Fähigkeit. Die Fähigkeit von Mightling ist diejenige, die 68 gelöste Aufgaben bei diesen 100 erklärt; ≈69 % ist der erwartete Wert dieser Fähigkeit auf allen 500 (eine einfache Regression auf die veröffentlichten Werte stimmt auf einen Punkt genau überein). Zur Kontrolle wurde jede öffentliche Einreichung allein auf diesen 100 Aufgaben bewertet und ihr Gesamtergebnis auf dieselbe Weise vorhergesagt: Der Fehler betrug 2,4 Punkte (RMSE), und das Band oben ist ±1,96-mal so breit. Jede Zahl in der Tabelle lässt sich mit scripts/swe_bench_compare.py aus den öffentlichen Daten pro Aufgabe von SWE-bench/experiments reproduzieren.

Die 100 Aufgaben verteilen sich im Verhältnis zum ganzen Set auf die Repositories von Verified, und zwar unter den Aufgaben, deren Testumgebung auf arm64 läuft und validiert (der Gold-Patch besteht, eine leere Änderung scheitert). Veröffentlichte Systeme erzielen auf diesen 100 Aufgaben 1,0 bis 1,5 Punkte weniger als auf allen 500, die Stichprobe ist also keine leichte. Es ist kein Leaderboard-Eintrag: Diese werden vom SWE-bench-Team auf dessen eigener Infrastruktur bewertet.

Dein Code verlässt nie deinen Schreibtisch – und du kannst es beweisen

Cloud-Coding-Agenten schicken deinen Quellcode an die Server anderer. Mightling schickt ihn nirgendwohin: Das Modell läuft auf deinem GB10, und nichts an Mightling telefoniert nach Hause. Keine Nutzungsanalyse, keine Metriken, keine Anmeldung, keine „anonymen“ Absturzberichte. Damit ist es auch für Code geeignet, den du nicht hochladen darfst: Kundenprojekte, regulierte Daten, unveröffentlichte Produkte.

Ein Befehl startet eine echte Mightling-Sitzung unter strace und listet jede Netzwerkverbindung auf, die sie aufgebaut hat:

$ ling-admin audit egress
✔ Egress audit: pass
Network destinations:
   127.0.0.1:8000     29x  model server
   127.0.0.1:8767      1x  Gmail search service
DNS queries: none
Networked git commands: none

Alles blieb auf 127.0.0.1. Keine einzige DNS-Abfrage.

Du brauchst eine harte Garantie?

Tippe /airgapped on, und jeder Befehl, den der Agent ausführt, bekommt vom Linux-Kernel einen leeren Netzwerk-Namespace. Das ist keine höfliche Bitte an das Modell: Es gibt schlicht kein Netzwerk, das sich erreichen ließe. Full Access, der die Sandbox umgehen würde, wird gleichzeitig abgelehnt.

Was hinaus darf, und wann

Nur, was du oder der Agent anfordert: eine Websuche (über ein privates SearXNG auf deinem eigenen Rechner), ein Seitenabruf, eine schreibgeschützte Anfrage an ein verbundenes Google-Konto oder eine Update-Prüfung. Bei /airgapped on nichts davon.

Warum Mightling

🔒 Vertraulich

Das Modell, dein Code, deine Prompts und die Antworten bleiben auf dem Rechner, auf dem sie sind.

  • Kein Konto, keine Telemetrie
  • Egress-Audit, das du wiederholen kannst
  • /airgapped on, vom Kernel durchgesetzt

⚡ Schnell, ohne Rechnung

Ein Stream auf einem GB10 mit spekulativem Decoding. Agentenarbeit wird über echte Agentensitzungen gemessen; Code, JSON und Prosa nach Art der Ausgabe, mit Greedy Decoding. Lass vier Agenten gleichzeitig laufen: kein Kontingent, kein „bitte warten“.

✨ Nichts zu konfigurieren

  • Kein Tuning: Modell, Kontext, Kernel und spekulatives Decoding sind auf den GB10 abgestimmt.
  • Es friert deinen Rechner nicht ein: Der Host wird geprüft, und der Speicherdruck wird beim Laden überwacht.
  • Deine anderen Rechner finden es im lokalen Netzwerk.
  • Updates sind ein Befehl: ling update.

FAQ

Brauche ich einen GB10?

Ja, um das Modell auszuführen. Deine anderen Rechner nutzen ihn als Clients: Linux (Arm oder x86) und macOS mit demselben Installationsbefehl, Windows (Arm oder x86, Vorschau) mit der PowerShell-Zeile.

Ich habe Puffin installiert. Ist das dasselbe?

Ja: Puffin wurde in 1.5 in Mightling umbenannt. Führe einmal puffin update aus, dann ein letztes Mal puffin. Das überträgt deine Sitzungen, Einstellungen und Verknüpfungen, und der Befehl lautet danach ling.

Ist es wirklich kostenlos?

Ja. Mightling ist Open Source unter der AGPL, und die Gewichte des Modells sind frei. Deine einzigen laufenden Kosten sind der Strom.

Was brauche ich außer der Maschine?

Das mitgelieferte Betriebssystem (DGX OS 7 oder Ubuntu 24.04, wo der Hersteller es anbietet), Docker mit dem NVIDIA Container Toolkit, Python 3 und Git. Auf einem normalen Ubuntu sagt dir ling-admin host check, was fehlt.

Gelangt jemals etwas ins Internet?

Nur, was du oder der Agent anfordert, etwa eine Websuche über SearXNG auf deinem eigenen Rechner, sowie die Downloads beim ersten Mal. /airgapped on schaltet alles davon ab.

Welches Modell läuft darauf?

Qwen3.8-27B im 4-Bit-Format NVFP4 von NVIDIA, bereitgestellt von SGLang mit einem DFlash2-Drafter, für den GB10 ausgewählt und abgestimmt. Etwa 20 GB Gewichte; rund 38 GB des Maschinenspeichers bleiben frei, während es läuft.
