Installation

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
$ ling-admin server start      # lädt das Modell einmal herunter (~20 GB) und startet es dann
$ cd ~/your-project && ling    # das war alles

Das funktioniert auf dem NVIDIA DGX Spark und auf jedem anderen GB10-Rechner. Das Skript prüft jeden Download anhand der Prüfsummen des Releases und zeigt dir jeden sudo-Befehl, bevor es ihn ausführt. Du kannst das Skript vorher lesen.

Mac- und Linux-Clients

Deine anderen Computer leihen sich das Modell des GB10 über dein Heim- oder Büronetz. Auf einem Mac oder einem anderen Linux-Rechner installiert derselbe Befehl ling, den Teil, in den du tippst. Er findet den GB10 von selbst.

Ab 1.7.2 legt er auf einem Mac auch die Desktop-App in den Ordner „Programme“, fertig zum Öffnen. Mit --no-app lässt du sie weg.

Windows-Client Vorschau

> irm https://github.com/dreamference/mightling/releases/latest/download/install.ps1 | iex

Gib das in PowerShell ein. Du brauchst dafür keine Administratorrechte (ab 1.7.2 gilt das auch für die Desktop-App). Windows fragt dich dann einmal, ob es einen abgeschotteten Raum einrichten soll, in dem der Helfer Befehle ausführt. Der Installer ist noch nicht signiert, deshalb muss die intelligente App-Steuerung (Smart App Control) aus sein. Skript lesen.

Probier zuerst diese

Oder lass Arbeit für heute Nacht da mit /night add <task>. Mightling arbeitet die Liste ab, während du schläfst, jede Aufgabe auf einem eigenen Git-Branch, und am Morgen siehst du die Branches durch.

$ ling "explain this repository to me like I'm new on the team"
# reads the code index (ling-code outline, def, refs, callers) instead of grepping,
# then walks you through the layout, the entry points and how they connect
$ ling "the tests are failing: find out why and fix them"
# runs the tests, reads the failure, edits the code and runs the tests again,
# asking before anything risky
> /night add --best-of 3 add input validation to the signup form, with tests
# tonight: three attempts, each in its own git worktree; the one the chooser picks
# is committed on its own branch, and nothing is merged or pushed
$ ling-admin night status      # the timer, the window and the queue
> /night apply <id>            # in the morning: bring the branch back as uncommitted changes

🧭 Ein Code-Index

Eine Liste, wo Dinge definiert sind und wer sie benutzt, über dein ganzes Projekt, damit der Helfer Code nachschlagen kann, statt ihn zu erraten.

🔎 Websuche und Seitenabruf

Die Suche läuft über ein privates SearXNG auf deinem eigenen Rechner, du brauchst also kein Suchkonto und keinen Schlüssel. Die Fragen gehen trotzdem ins Web, damit sie beantwortet werden.

🌙 Night Shift

Tippe vor dem Schlafengehen /night add <task>. Bis zum Morgen ist jede Aufgabe auf einem eigenen Git-Branch erledigt. Nichts wird zusammengeführt oder gepusht, wenn du es nicht tust.

Was du bekommst

Die Desktop-App in 1.7.0 vereint beide Arten, Mightling zu nutzen, in einem Fenster: Ask, wo du Fragen stellst, und Work, wo der Helfer deinen Code ändert. Work hat ein Eingabefeld für Aufgaben (du kannst Dateien, Skills und Befehle anhängen), einen Bereich, in dem du Änderungen prüfst, bevor du sie behältst oder zurücknimmst, getrennte Arbeitskopien deines Codes (Worktrees), Terminal-Tabs und einen Dateibaum neben dem Gespräch. Auf deinen anderen Computern spricht die App mit deinem GB10, den sie in deinem Netz findet.

Dein Code bleibt auf deinem Schreibtisch, und du kannst das nachprüfen

Ein Cloud-Coding-Helfer schickt deinen Quellcode an Computer, die jemand anderem gehören. Mightling schickt ihn nirgendwohin. Das Modell läuft auf deinem GB10, und nichts in Mightling meldet sich zu Hause: keine Nutzungszähler, keine Messungen, keine Anmeldung, nicht einmal „anonyme“ Absturzberichte. So kannst du es für Code nutzen, den du nicht hochladen darfst, etwa die Arbeit eines Kunden, geschützte Daten oder ein noch unveröffentlichtes Produkt.

Ein Befehl startet eine echte Mightling-Sitzung unter strace, einem Werkzeug, das jeden Aufruf eines Programms beobachtet, und listet dann jede Netzwerkverbindung auf, die die Sitzung geöffnet hat:

$ ling-admin audit egress
✔ Egress audit: pass
Network destinations:
   127.0.0.1:8000     29x  model server
   127.0.0.1:8767      1x  Gmail search service
DNS queries: none
Networked git commands: none

Alles blieb auf 127.0.0.1, das heißt, der Rechner hat nur mit sich selbst gesprochen. Es gab keine einzige DNS-Anfrage (eine DNS-Anfrage fragt das Internet nach der Adresse zu einem Namen).

Du willst eine feste Garantie?

Tippe /airgapped on. Jeder Befehl, den der Helfer ausführt, bekommt dann vom Linux-Kernel ein leeres Netzwerk. Das ist keine höfliche Bitte an das Modell. Es gibt einfach kein Netzwerk, das man erreichen könnte. Gleichzeitig wird Full Access abgelehnt, das die Sandbox umgehen würde.

Was hinaus darf, und wann

Nur das, was du oder der Helfer verlangen: eine Websuche (über ein privates SearXNG, das auf deinem eigenen Rechner läuft; die Suche selbst geht aber ins Web), das Abrufen einer Webseite, eine Leseanfrage an ein Google-Konto, das du verbunden hast, oder die Suche nach Updates. Mit /airgapped on passiert nichts davon.

Warum Mightling

🔒 Privat

Das Modell, dein Code, deine Fragen und seine Antworten bleiben auf dem Rechner, auf dem sie sind.

  • Kein Konto, kein Tracking
  • Ein Egress-Audit, das du jederzeit wiederholen kannst
  • /airgapped on, vom Kernel durchgesetzt

⚡ Schnell, und ohne Rechnung

Arbeit am Code~48 tok/s
Code schreiben69 tok/s
JSON84 tok/s
Prosa32 tok/s
Code lesen~1,800 tok/s
Gedächtnis des Gesprächs262K

Das sind Geschwindigkeiten für eine einzelne Aufgabe auf einem GB10. Das Modell nutzt einen Trick namens Speculative Decoding: Ein kleiner Helfer rät mehrere Wörter voraus, und das große Modell prüft alle Vermutungen auf einmal. „Arbeit am Code“ ist über echte Helfer-Sitzungen gemessen. Code, JSON und Fließtext wurden jeweils an dieser Art von Ausgabe gemessen. Die letzte Zeile zeigt, wie viel Text es auf einmal im Kopf behalten kann: 262K Tokens, das sind einige hundert Seiten. Lass gern vier Helfer gleichzeitig laufen. Es gibt kein Kontingent und kein „bitte warten“.

✨ Kaum Einrichtung

  • Kein Feintuning nötig: Wir haben das Modell, die Speichergröße, den Low-Level-Code und das Speculative Decoding für den GB10 ausgewählt.
  • Es soll deinen Rechner nicht einfrieren: Es prüft den Rechner, bevor es das Modell lädt, und beobachtet beim Laden den Speicher.
  • Deine anderen Computer finden es in deinem Netz.
  • Ein Update ist ein Befehl: ling update.

SWE-bench Verified, gemessen auf einem DGX Spark

SWE-bench Verified ist eine Sammlung von 500 echten Problemen aus Open-Source-Programmen. Bei jedem muss der Helfer den Code so ändern, dass die Tests bestehen. Am 08.10.2026 haben wir 100 davon Mightling 1.5.1 gegeben, mit dem Modell Qwen3.8-27B, auf einem einzigen DGX Spark ohne Internet. Er hatte pro Aufgabe einen Versuch, im Standardmodus, und hat 68 der 100 gelöst. Rechnen wir das auf alle 500 hoch, schätzen wir etwa 69 %, plus/minus ein paar Punkte (der 95-%-Bereich geht von 63,9 bis 73,4 %). Das haben wir selbst gemessen, auf unserem eigenen Rechner, an einer Stichprobe der Aufgaben. Es ist kein Eintrag in der offiziellen Bestenliste.

Lies diese Tabelle als Hilfe, um zu sehen, wer in der Nähe liegt, nicht als Rangliste. Bei denselben 100 Aufgaben hat Mightling so viele gelöst wie Qwen3-Coder-480B und GLM-4.6, Modelle, die um ein Vielfaches größer sind. Aber jede Zeile benutzt ein anderes Helferprogramm und andere Hardware, und die Zeilen der Bestenliste nutzten die offiziellen Test-Images für x86-Rechner, unsere liefen auf Community-Images für arm64. Es gibt auch einen zweiten Modus namens refine. Eine erste Sitzung untersucht das Problem und ändert nichts, dann erledigt eine frische Sitzung die Arbeit. Er hat eine Aufgabe mehr gelöst als der Standard (69 gegen 68, und jeder Modus hat einige Aufgaben gelöst, die der andere verfehlt hat), und er brauchte pro Aufgabe etwa 2,2-mal so lange. Deshalb ist er aus, außer du verlangst ihn mit ling --refine.

So schätzen wir die 69 %

100 Aufgaben sind ein Fünftel von Verified, die Zahl für alle 500 ist also eine Schätzung. So sind wir vorgegangen. Wir nehmen die Ergebnisse aller 175 öffentlichen Verified-Einreichungen, Aufgabe für Aufgabe. Mit einem Item-Response-Modell mit einem Parameter (Rasch) geben wir jeder Aufgabe eine Schwierigkeit und jedem System eine Fähigkeit. Die Fähigkeit von Mightling ist die, die bei diesen 100 Aufgaben 68 lösen würde, und etwa 69 % ist das, was diese Fähigkeit bei allen 500 erreichen würde. Eine einfache Regression über die veröffentlichten Werte stimmt bis auf einen Punkt überein. Wir haben die Methode auch an anderen geprüft: Für jede öffentliche Einreichung haben wir nur ihr Ergebnis bei diesen 100 Aufgaben genutzt, um ihr Ergebnis bei allen 500 vorherzusagen. Der Fehler lag bei 2,4 Punkten (RMSE), und der Bereich oben ist das 1,96-Fache davon nach jeder Seite. Jede Zahl in der Tabelle lässt sich mit scripts/swe_bench_compare.py nachrechnen, aus den öffentlichen Daten pro Aufgabe in SWE-bench/experiments.

Wir haben die 100 Aufgaben im selben Verhältnis wie im vollen Set auf die Programme in Verified verteilt. Wir haben sie aus den Aufgaben gezogen, deren Testaufbau auf arm64 funktioniert und stimmt (die richtige Korrektur besteht, und nichts zu tun fällt durch). Veröffentlichte Systeme erreichen bei diesen 100 Aufgaben 1,0 bis 1,5 Punkte weniger als bei allen 500, die Stichprobe ist also nicht leicht. Ein Eintrag in der Bestenliste ist sie trotzdem nicht, denn das SWE-bench-Team bewertet diese auf seinen eigenen Rechnern.

FAQ

Brauche ich einen GB10?

Ja, um das Modell auszuführen. Deine anderen Computer sind Clients, die es sich leihen: Linux (Arm oder x86) und macOS mit demselben Installationsbefehl, und Windows (Arm oder x86, Vorschau) mit der PowerShell-Zeile.

Ich habe Puffin installiert. Ist das dasselbe Programm?

Ja. Puffin wurde in 1.5 in Mightling umbenannt. Führe einmal puffin update aus und danach ein letztes Mal puffin. Das überträgt deine Sitzungen, Einstellungen und Verknüpfungen, und danach heißt der Befehl ling.

Kostet es wirklich nichts?

Nichts für das Programm und nichts für das Modell. Mightling ist Open Source unter der AGPL, und die Gewichte des Modells sind frei nutzbar. Du bezahlst den Rechner und den Strom, den er braucht.

Was brauche ich außer der Maschine?

Das mitgelieferte Betriebssystem (DGX OS 7, oder Ubuntu 24.04, wo NVIDIA es anbietet), Docker mit dem NVIDIA Container Toolkit, Python 3 und Git. Auf einem normalen Ubuntu sagt dir ling-admin host check, was fehlt.

Geht jemals etwas ins Internet?

Nur das, was du oder der Helfer verlangen, etwa eine Websuche (über ein SearXNG, das auf deinem eigenen Rechner läuft) und die Downloads bei der ersten Nutzung. Mit /airgapped on ist das alles aus.

Welches Modell läuft darauf?

Qwen3.8-27B im 4-Bit-Format von NVIDIA namens NVFP4, bereitgestellt von SGLang mit einem kleinen Rate-Helfer, dem DFlash2-Drafter. Wir haben alles für den GB10 ausgewählt und abgestimmt. Die Gewichte brauchen etwa 20 GB, und während es läuft, bleiben etwa 38 GB des Speichers frei.

Behalte deinen Code auf deinem Schreibtisch

Wenn du findest, dass Code dort bleiben sollte, wo er geschrieben wurde, gib dem Repository auf GitHub einen Stern. So finden andere GB10-Besitzer Mightling.

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
