Aussi dans la 1.7.0 : Night Shift peut essayer une tâche plusieurs fois et garder le meilleur essai (/night add --best-of N). Une machine peut faire tourner plusieurs ponts Signal. Et un ordinateur qui voit deux GB10 sur un même réseau peut choisir entre eux sans oublier celui qu'il connaît déjà. Notes de version et téléchargements.

Installer

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
$ ling-admin server start      # télécharge le modèle une seule fois (~20 Go), puis le démarre
$ cd ~/your-project && ling    # c'est tout

Cela fonctionne sur le NVIDIA DGX Spark et sur toute autre machine GB10. Le script vérifie chaque téléchargement avec les sommes de contrôle de la version, et vous montre chaque commande sudo avant de l'exécuter. Vous pouvez lire le script d'abord.

Clients Mac et Linux

Vos autres ordinateurs empruntent le modèle du GB10 par votre réseau de la maison ou du bureau. Sur un Mac ou une autre machine Linux, la même commande installe ling, la partie dans laquelle vous tapez. Elle trouve le GB10 toute seule.

Depuis la 1.7.2, elle place aussi l'application de bureau dans Applications sur un Mac, prête à ouvrir. Ajoutez --no-app si vous n'en voulez pas.

Client Windows preview

> irm https://github.com/dreamference/mightling/releases/latest/download/install.ps1 | iex

Tapez ceci dans PowerShell. Il ne faut aucun droit d'administrateur (depuis la 1.7.2, c'est vrai aussi pour l'application de bureau). Windows vous demande ensuite une fois de préparer un espace clos où l'assistant exécute des commandes. Le programme d'installation n'est pas encore signé : le contrôle intelligent des applications (Smart App Control) doit donc être désactivé. Lire le script.

Autres façons d'installer

La page de la version propose aussi l'image disque pour Mac (Mightling-<version>-arm64-preview.dmg, ou x64 pour Intel) et le programme d'installation Windows (Mightling-Setup-<version>-x64.exe, ou arm64). Ce sont des préversions non signées : quand vous les téléchargez dans un navigateur, votre système les bloque la première fois. Avant d'en ouvrir une, comparez-la au fichier signé SHA256SUMS de la version.

  • macOS 15 et plus récent : faites glisser Mightling dans Applications et ouvrez-le une fois. Allez ensuite dans Réglages Système › Confidentialité et sécurité et cliquez sur Ouvrir quand même. Sur macOS 14 et plus ancien, faites Contrôle-clic sur l'application et choisissez Ouvrir.
  • Windows : SmartScreen › Informations complémentaires › Exécuter quand même. Smart App Control doit être désactivé.

À essayer d'abord

Ou laissez du travail pour cette nuit avec /night add <task>. Mightling parcourt la liste pendant que vous dormez, chaque tâche sur sa propre branche git, et vous examinez les branches le matin.

$ ling "explain this repository to me like I'm new on the team"
# reads the code index (ling-code outline, def, refs, callers) instead of grepping,
# then walks you through the layout, the entry points and how they connect
$ ling "the tests are failing: find out why and fix them"
# runs the tests, reads the failure, edits the code and runs the tests again,
# asking before anything risky
> /night add --best-of 3 add input validation to the signup form, with tests
# tonight: three attempts, each in its own git worktree; the one the chooser picks
# is committed on its own branch, and nothing is merged or pushed
$ ling-admin night status      # the timer, the window and the queue
> /night apply <id>            # in the morning: bring the branch back as uncommitted changes

Une liste de l'endroit où les choses sont définies et de qui les utilise dans tout votre projet, pour que l'assistant consulte le code au lieu de le chercher au hasard.

🔎 Recherche web et récupération de pages

La recherche passe par un SearXNG privé sur votre propre machine : pas de compte de recherche, pas de clé à obtenir. Les questions partent tout de même sur le web pour recevoir une réponse.

🌙 Night Shift

Tapez /night add <task> avant de vous coucher. Au matin, chaque tâche est faite sur sa propre branche git. Rien n'est fusionné ni poussé sans vous.

Ce que vous obtenez

L'application de bureau de la 1.7.0 réunit dans une seule fenêtre les deux façons d'utiliser Mightling : Ask, où vous posez des questions, et Work, où l'assistant modifie votre code. Work a une zone pour taper les tâches (vous pouvez joindre des fichiers, des skills et des commandes), un volet pour examiner les changements avant de les garder ou de les annuler, des copies de travail séparées de votre code (worktrees), des onglets de terminal et une arborescence de fichiers à côté de la conversation. Sur vos autres ordinateurs, l'application parle à votre GB10, qu'elle trouve sur votre réseau.

Votre code reste sur votre bureau, et vous pouvez le vérifier

Un assistant de code dans le cloud envoie votre code source à des ordinateurs qui appartiennent à quelqu'un d'autre. Mightling ne l'envoie nulle part. Le modèle tourne sur votre GB10, et rien dans Mightling n'appelle l'extérieur : pas de compteur d'usage, pas de mesures, pas de connexion, pas même de rapports de plantage « anonymes ». Vous pouvez donc l'utiliser sur du code que vous n'avez pas le droit d'envoyer, comme le travail d'un client, des données protégées ou un produit pas encore sorti.

Une commande lance une vraie session Mightling sous strace, un outil qui observe chaque appel d'un programme, puis liste chaque connexion réseau ouverte par la session :

$ ling-admin audit egress
✔ Egress audit: pass
Network destinations:
   127.0.0.1:8000     29x  model server
   127.0.0.1:8767      1x  Gmail search service
DNS queries: none
Networked git commands: none

Tout est resté sur 127.0.0.1, c'est-à-dire la machine qui parle à elle-même. Il n'y a pas eu une seule requête DNS (une requête DNS demande à Internet l'adresse qui correspond à un nom).

Vous voulez une garantie ferme ?

Tapez /airgapped on. Chaque commande que l'assistant exécute reçoit alors un réseau vide, fourni par le noyau Linux. Ce n'est pas une demande polie au modèle. Il n'y a tout simplement aucun réseau à atteindre. En même temps, Full Access, qui contournerait le bac à sable, est refusé.

Ce qui peut sortir, et quand

Seulement ce que vous ou l'assistant demandez : une recherche web (par un SearXNG privé qui tourne sur votre propre machine, même si la recherche elle-même part sur le web), la récupération d'une page web, une requête en lecture seule vers un compte Google que vous avez connecté, ou une recherche de mises à jour. Avec /airgapped on, rien de tout cela n'arrive.

SWE-bench Verified, mesuré sur un seul DGX Spark

SWE-bench Verified est un ensemble de 500 vrais problèmes tirés de programmes open source. Pour chacun, l'assistant doit modifier le code pour que les tests passent. Le 2026-10-08, nous en avons donné 100 à Mightling 1.5.1, avec le modèle Qwen3.8-27B, sur un seul DGX Spark sans Internet. Il avait un seul essai pour chacun, dans son mode par défaut, et il a résolu 68 problèmes sur 100. Si on étend cela aux 500, nous estimons environ 69 %, à quelques points près (l'intervalle à 95 % va de 63,9 à 73,4 %). Nous l'avons mesuré nous-mêmes, sur notre propre machine, sur un échantillon de problèmes. Ce n'est pas une entrée du classement officiel.

Lisez ce tableau pour voir qui est proche, pas comme un classement. Sur les mêmes 100 problèmes, Mightling en a résolu autant que Qwen3-Coder-480B et GLM-4.6, des modèles bien plus grands que lui. Mais chaque ligne utilise un autre programme d'assistance et un autre matériel, et les lignes du classement utilisaient les images de test officielles pour les ordinateurs x86, alors que les nôtres tournaient sur des images communautaires pour arm64. Il existe aussi un second mode, appelé refine. Une première session étudie le problème sans rien changer, puis une nouvelle session fait le travail. Il a résolu un problème de plus que le mode par défaut (69 contre 68, et chaque mode a résolu des problèmes que l'autre a ratés), et il a pris environ 2,2 fois plus de temps par problème. Il est donc désactivé, sauf si vous le demandez avec ling --refine.

Comment nous estimons les 69 %

100 problèmes font un cinquième de Verified, donc le chiffre pour les 500 est une estimation. Voici comment nous l'avons obtenu. On prend les résultats des 175 soumissions publiques de Verified, problème par problème. On donne à chaque problème une difficulté et à chaque système une capacité, avec un modèle de réponse à l'item (Rasch) à un paramètre. La capacité de Mightling est celle qui résoudrait 68 de ces 100 problèmes, et environ 69 % est ce que cette capacité obtiendrait sur les 500. Une simple régression sur les scores publiés donne le même résultat à un point près. Nous avons aussi vérifié la méthode sur d'autres systèmes : pour chaque soumission publique, nous avons utilisé seulement son score sur ces 100 problèmes pour prédire son score sur les 500. L'erreur était de 2,4 points (RMSE), et l'intervalle ci-dessus vaut 1,96 fois cette erreur de chaque côté. Chaque nombre du tableau peut être reproduit avec scripts/swe_bench_compare.py, à partir des données publiques par problème de SWE-bench/experiments.

Nous avons réparti les 100 problèmes entre les programmes de Verified dans les mêmes proportions que l'ensemble complet. Nous les avons tirés parmi les problèmes dont la mise en place des tests fonctionne et se vérifie sur arm64 (le bon correctif passe, et ne rien faire échoue). Les systèmes publiés obtiennent 1,0 à 1,5 point de moins sur ces 100 que sur les 500, l'échantillon n'est donc pas facile. Ce n'est toujours pas une entrée du classement, car l'équipe SWE-bench les évalue sur ses propres machines.

FAQ

Ai-je besoin d'un GB10 ?

Oui, pour exécuter le modèle. Vos autres ordinateurs sont des clients qui l'empruntent : Linux (Arm ou x86) et macOS avec la même commande d'installation, et Windows (Arm ou x86, préversion) avec la ligne PowerShell.

J'ai installé Puffin. Est-ce le même programme ?

Oui. Puffin a été renommé Mightling dans la 1.5. Lancez puffin update une fois, puis puffin une dernière fois. Il déplace vos sessions, réglages et liens, et ensuite la commande est ling.

Est-ce vraiment gratuit ?

Rien à payer pour le programme ni pour le modèle. Mightling est open source sous licence AGPL, et les poids du modèle sont libres d'utilisation. Vous payez la machine et l'électricité qu'elle consomme.

De quoi ai-je besoin en plus de la machine ?

Le système d'exploitation fourni (DGX OS 7, ou Ubuntu 24.04 là où NVIDIA le propose), Docker avec le NVIDIA Container Toolkit, Python 3 et Git. Sur un Ubuntu ordinaire, ling-admin host check vous dit ce qui manque.

Quelque chose sort-il jamais vers Internet ?

Seulement ce que vous ou l'assistant demandez, comme une recherche web (par un SearXNG qui tourne sur votre propre machine) et les téléchargements du premier usage. Avec /airgapped on, tout cela est coupé.

Quel modèle fait-il tourner ?

Qwen3.8-27B, dans le format 4 bits de NVIDIA appelé NVFP4, servi par SGLang avec un petit assistant de devinettes appelé drafter DFlash2. Nous avons tout choisi et réglé pour le GB10. Les poids prennent environ 20 Go, et pendant l'exécution, il reste environ 38 Go de mémoire libres sur la machine.

Gardez votre code sur votre bureau

Si vous pensez que le code doit rester sur le bureau où il a été écrit, mettez une étoile au dépôt sur GitHub. C'est ainsi que les autres propriétaires de GB10 trouvent Mightling.

$ curl -fsSL https://github.com/dreamference/mightling/releases/latest/download/install.sh | bash
