# The egress audit

Developer notes behind the egress-audit line in `AGENTS.md`. Spec: `specs/DREAMFERENCE_MIGHTLING_EGRESS.md` §10. The channels it found are listed in [launcher.md](launcher.md#channels-to-the-vendor-closed).

`ling-admin audit egress` is the trace that found the upstream vendor's channels, as a command (`dreamference/audit/`). It runs one real `ling exec` under `strace -f -e trace=connect,sendto,sendmsg,sendmmsg,execve` in a throwaway repository and `CODEX_HOME`, and passes only if every IP destination is an allowlisted loopback port (the model server, Gmail on 8767, SearXNG on 8888, image search on 8768), no DNS query was sent and no git command reached a network; exit 0, 1 or 2 (the trace itself failed, which is never a pass).

Two things the parser had to learn from a recording: glibc sends lookups with `sendmmsg` (untraced, a query leaves no name), and a connect to `127.0.0.53:53` is loopback yet still a query that leaves the machine.

Modes:

- `--tui` traces the full-screen interface, which starts things `exec` never does. `ling-admin codex build` runs both the `exec` and the `--tui` trace after installing a new binary (`--no-audit` skips it; without a model server it says so and does not wait).
- `--app` checks the desktop app, including a preview tab of the audit's own loopback page that reaches for the internet every way a page can (Phase 3 item 4); see [desktop.md](desktop.md).
- `--compat claude` traces the compatibility mode's print mode (`ling --compat claude -p … --output-format json`) in a throwaway repository holding Claude Code's files: a `CLAUDE.md`, a `.claude/settings.json` with a hook and a permission rule, a command and an agent (`dreamference/audit/compat_print_session.py`), and a `.mcp.json` with a stdio server the audit approves (`ling compat mcp approve fixture`, in the throwaway home) and an unapproved HTTP server that must never be connected. `codex build` runs it as a third trace when the user's new sessions start in the mode.
- `--web` traces `ling web serve` answering an Ask thread; where image search is set up on this machine (its secret file exists), it asks a second question that calls `image_search`, in a scratch home laid out as a node with a copy of that secret and a `ling-admin` that runs the code under audit (`write_admin`; not a link to `~/.local/bin/ling-admin`, which on 2026-10-15 was main's environment without `images mcp`, so the tool never started and the model answered without an image). Before asking, the audit starts that server as Codex will and asks for its tools; one that cannot start is named (`not asked: …`). The report says what came of it (`Image search turn: …`, also in the JSON), and `answered with an image` only when the answer names an image the service holds in its store (the service logs no request; the store is the evidence). The tool's MCP server is traced with the app-server; its connection to 8768 is allowed. Without image search the turn is skipped and the report says so.
- `--docs` proves the local file index opens no socket; see [local-file-index.md](local-file-index.md).
- `--sync` traces one sync agent cycle (`ling sync agent --once`) of a throwaway device paired with a throwaway hub on loopback: only the hub's port may be reached, no name looked up, and the device's `ling exec` session must stay off the hub; see [sync.md](sync.md).

Re-run it after any Codex bump. The airlock (Phase 2) is not built.

**Plugins.** Every mode runs in a throwaway `CODEX_HOME` with no plugin installed and no marketplace added, so it proves Mightling's own channels and the vendor's closed ones (the curated sync and featured list, patch 0015; the remote catalogue and sharing, off in `config.toml`), not a plugin's. Plugins are allowed at `/airgapped off` since 2026-10-22: adding a marketplace or installing a plugin runs `git` (and, for an imported Claude Code plugin, `npm`) in `ling`'s own process, and a plugin's MCP servers and hooks run outside the sandbox, so traffic a user's plugin makes is the user's choice, as with an MCP server they configured. At a configured `on` no plugin loads and no install runs ([airgapped.md](airgapped.md#plugins)).

**Declared exceptions.** The phone messengers talk to outside services by design, outside any traced session, and only once turned on. Every report ends with one line per bridge that is on (`EgressAudit.declared_exceptions`): the system unit `mightling-signal.service` (signal-cli to Signal's servers), the user unit `mightling-chat.service` with a Telegram token (the Bot API), and the user socket `mightling-matrix-proxy.socket` (the homeserver offered to the tailnet, with push on or off). With every bridge off it adds nothing, and they never change the verdict. See [messengers.md](messengers.md). The node's forge is named the same way while `mightling-forge.service` is enabled, with each GitHub destination its mirror sends to (or none); see [forge.md](forge.md).

Every unattended caller of `ling` (Night Shift, the egress audit, SWE-bench, the Codex test runner) names the model server in `DREAMFERENCE_VLLM_HOST`, because a node browse is a multicast DNS query and the audit counts one as a failure.

The audit does not cover a proxy variable left in the user's shell. `ling` and `ling-admin` exempt loopback and the model server from it through `NO_PROXY` instead (spec §11; [launcher.md](launcher.md#what-the-launcher-does)).
