# The `ling` launcher and its home folder

Developer notes behind the launcher summary in `AGENTS.md`. Specs: `specs/DREAMFERENCE_MIGHTLING_CODEX.md`, `specs/DREAMFERENCE_MIGHTLING_EGRESS.md`. How the binary is built: [codex-build.md](codex-build.md).

## What the launcher does

The launcher (`ling-rs/src/lib.rs`) is what the Python runner used to do, and `CodexRunner` now only builds and execs `ling`. Before Codex parses its arguments it skips everything for `--version`/`--help`/offline subcommands; otherwise it:

- resolves the vLLM URL (`DREAMFERENCE_VLLM_HOST`, then `vllm_host` in `DREAMFERENCE_CONFIG_PATH`, `./dreamference.toml` or `~/.config/dreamference/config.toml`; a repository's `./dreamference.toml` may set no network key, not even a server on this machine: `vllm_host` there is ignored with one line naming the file and the key, the user's file deciding; on a client, the node tiers in [node.md](node.md));
- waits for the server with the old dotted progress;
- reads the served model's id **and `max_model_len` from `/v1/models`**, so it needs no copy of the model registry;
- writes `$CODEX_HOME/model_catalog.json` (Codex's own prompt plus `WEB_ACCESS_INSTRUCTIONS`; see [prompt.md](prompt.md) for named prompts). The entry offers `apply_patch` in its freeform (custom-tool) form only when `/v1/models` reports `owned_by: ling-engine`: SGLang and vLLM drop a `custom` tool silently (measured 2026-10-10), ling-engine runs it (verified the same day). `ServedModel::runs_custom_tools` is the one gate, and `DREAMFERENCE_MIGHTLING_APPLY_PATCH=off|function|freeform` overrides it for a benchmark arm; a test pins both (Codex spec §"Writes model_catalog.json");
- has Code Mode's `exec` translated where the server drops custom tools (since 2026-10-12, reversing the ling-engine-only choice of 2026-10-10): on any server but ling-engine (the same gate), `ling-rs/tools/src/custom.rs`, called from patch 0020's hooks, sends `exec` as a function with one string parameter `input` and the grammar in its description, exactly as ling-engine renders it, turns the model's function call back into the `custom_tool_call` Codex expects before Codex records it, and replays earlier calls and outputs as function calls and outputs. `src/exec_tool.rs` sets the choice once per process; `DREAMFERENCE_MIGHTLING_EXEC_TOOL=freeform` turns it off (the Code Mode A/B's off arm), `=function` forces it. Where `exec` stays custom on such a server (`freeform`), Code Mode's `wait`, a function, is left out of the request too (since 2026-10-13): offered alone it could never name a cell, and the model passed it `exec_command`'s session and chunk ids, 424 calls in the SWE-bench runs of 2026-10-08 to 10-12 and the compaction bench of 2026-10-13, every one "exec cell … not found"; in the bench the model then relaunched its test run instead of polling it with `write_stdin`, leaving runs overlapping. `apply_patch` is never translated;
- edits `config.toml` with `toml_edit` (so top-level keys can never be reparented into a table; `check_for_update_on_startup = false` because the update prompt would offer to replace Mightling with upstream Codex; `sandbox_workspace_write.network_access = true` when absent, so sandboxed commands have the network below `/airgapped on`; the read-only sandbox gets it from patch `0031`, and the catalog's `model_messages.permissions.read_only` says so: [airgapped.md](airgapped.md));
- prepends `--oss --local-provider openai-custom --model <id>` unless the user gave their own; `<id>` is the base or the session's adapter (below).
- registers the guards' two hooks (`ling guard <names>` under `PostToolUse` and `Stop`, `ling-rs/src/guard.rs`) when `DREAMFERENCE_MIGHTLING_TEST_GUARD` or `DREAMFERENCE_MIGHTLING_FINISH_CHECK` (or `mightling_test_guard`, `mightling_finish_check`) is on, for every session, `exec` included, and removes them otherwise; off by default until a night decides (SWE_BENCH spec §29). The guards' names are the hook's argument, not read from the environment when it runs: Codex gives a hook the session's environment snapshot, which may leave a variable out.

**Adapters** (`ling-rs/src/adapter.rs`; `specs/DREAMFERENCE_MIGHTLING_ADAPTERS.md` §10, §11.1; since 2026-10-20). The gate lists each verified adapter in `/v1/models` after the base as `<base>+<name>` with a `parent` naming the base; the launcher takes the base to be the first entry without a `parent` and writes one catalog entry per adapter after the base's own (the same entry under the adapter's id, `display_name` "Qwen3.8 27B · Rust", " (third-party)" at the end of one not signed by Dreamference, and the manifest's `description`), so `models[0]` stays the base for `ling web`, the desktop app, `ling skill` and Night Shift. The session's adapter, first match wins: `ling --adapter <name>` (removed before the subcommand is looked for), for `ling resume <id>`/`fork <id>` the thread's record `$CODEX_HOME/adapter/<thread-id>`, `DREAMFERENCE_MIGHTLING_ADAPTER`, `mightling_adapter` in the TOML file, the base. A tier set to `""` or `off` is the base and stops there, which is what lets the unattended callers (Night Shift, SWE-bench, the egress audit, the Codex test runner) set the variable empty without a user's default leaking in. A name the server does not list starts the session on the base with a notice. The record exists because Codex's own restore never runs under `ling`: `resume` keeps the thread's saved model only when no model or provider is overridden (`resume_model_settings_for_overrides` in the TUI), and the launcher always overrides both. `resume --last` and the picker name no thread at launch, so they start from the variable and the TOML file; a session started with `--adapter` is recorded only once `/adapter` is used in it. `/adapter` (patch 0028) reads the catalog, switches with `AppEvent::UpdateModel`, Codex's per-thread override, never `PersistModelSelection` (the global config), and writes the record; it never installs anything and names `ling-admin adapter install <name>` for one that is not listed.

Every surface sends reasoning effort `none` (the catalog's one level), so the model never thinks, and no sampling field: SGLang applies the checkpoint's `generation_config.json`. The loop guard ([loop-guard.md](loop-guard.md)) adds a per-response cap and a stream detector to every surface but `exec`, through Codex's extension API, installed from `airgapped::install`.

Two settings guard the connection to the local server:

- `stream_idle_timeout_ms = 900000` in the provider entry, only when absent. Upstream's 300 s idle timer is the only timeout before the first token, and it covers the server's queue as well as the prefill: one full KV pool (~157K tokens) is about 3 minutes, but three SWE-bench sessions queued behind each other can take 9 (`specs/DREAMFERENCE_MIGHTLING_CONTEXT_BUDGET.md` §1.10).
- `NO_PROXY` and `no_proxy`, extended first thing in `main()` with loopback and the model server's host, so a proxy left in the shell never sees local traffic (`ling-rs/src/proxy.rs`; `specs/DREAMFERENCE_MIGHTLING_EGRESS.md` §11). `ling-admin` does the same for itself and its children (`ProxyBypass`).

The web-access instructions are appended to the system prompt by the launcher (`WEB_ACCESS_INSTRUCTIONS` in `ling-rs/src/lib.rs`), so they apply in every workspace, not only this one.

## The compatibility mode

`ling --compat claude` (or `DREAMFERENCE_MIGHTLING_COMPAT=claude`, or `mightling_compat = "claude"` written by `ling compat use claude`) makes a session work the way Claude Code does (spec `specs/DREAMFERENCE_MIGHTLING_LING_CLAUDE.md`). `src/compat.rs` holds the switch. The flag becomes the variable first thing in `main()`, as refine's does (`home::use_mightling_home`), and is removed from the arguments before Codex parses them. The key is read **only** from the user's `~/.config/dreamference/config.toml`. One in a repository's `dreamference.toml` or in `DREAMFERENCE_CONFIG_PATH` is reported at start and ignored, so a clone cannot turn the mode on. A value naming no mode stops the start. Everything the mode does is gated on `compat::Mode::Claude`, and `ling compat doctor` reports what it reads. A TUI session in the mode gets `-c tui.*` overrides from `src/compat_tui.rs`, set ahead of the user's own `-c` so those still win, and never written to `config.toml`. They select the classic inline renderer, unless Claude Code's `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN`/`CLAUDE_CODE_NO_FLICKER`, Mightling's own `tui.*` screen setting or the settings files' `tui` key say otherwise, and Claude Code's key map (`Ctrl+O` for the transcript, `g`/`G`/`b` in the pager), minus any binding the user's `[tui.keymap]` decides. Codex's auto-review is switched off for the session (`features.guardian_approval=false`), because it asks a review model ling does not serve and `Shift+Tab` would otherwise cycle into it. Patch `0029` adds the mode's five TUI hooks, which call `src/compat_keys.rs`. `Enter` turns a trailing `\` into a newline, and runs Claude Code's command names under Codex's (`/branch`, `/tasks`, `/context`, …) or answers them (`/help`, `/memory`, `/config`, `/rewind`, `/login`, …). `Ctrl+C` and `Ctrl+D` on an empty prompt ask for a second press. In the transcript overlay, `[` adds the whole conversation, rendered from the session's rollout file, to the session's history, which the classic renderer keeps in the terminal's scrollback. Codex rebuilds that scrollback from its history after a redraw, so text written to the terminal directly would be lost. `v` opens the conversation in `$VISUAL`/`$EDITOR`. `Shift+Tab` cycles the approval modes, which never include Full Access. Outside the mode each call answers with Codex's own behaviour, and `compat_keys::force_on_this_thread` lets Codex's own tests switch the mode on. Claude Code's `CLAUDE.md` files reach a session in the mode through `src/compat_memory.rs`. It composes them as Claude Code's memory page documents (hierarchy, `@path` imports, comments dropped), deduplicates them against the `AGENTS.md` files Codex reads, and keeps them inside one 32 KiB budget with those files. The text arrives through a `SessionStart` hook, `ling compat memory`, registered with `-c` for the session's process and trusted in the session-flags layer (`/<session-flags>/config.toml:session_start:0:0`, given as an inline table). No patch is involved and nothing is written to `config.toml`. The settings files' hooks go into the same `-c hooks={…}` table (`src/compat_hooks.rs`).
- **Running:** each runs through `ling compat hook-shim -- '<command>'`, which translates the input and output to Claude Code's documented shapes. On Windows, Codex runs hooks through `cmd.exe /C`, which knows no single quotes, expands `%VAR%` inside double quotes and reads `&|<>^()` as operators: every hook line there puts the program in double quotes (`compaction::quote_program`) and passes the user's command, or a guard rule, as a hex word (`hook-shim --hex …`, `guard --deny-hex …`) that no shell rule touches. Single quotes there kept every hook from running, `CLAUDE.md` included (WINDOWS_ARM §23.4 W1). The shim runs the command in Git Bash, as Claude Code does on Windows (`CLAUDE_CODE_GIT_BASH_PATH`, or the `bash.exe` beside `git.exe` on `PATH`), else in `cmd.exe /C`.
- **Trust:** the user's own hooks are trusted beside them. A repository's hooks appear only in a trusted folder and wait for Codex's `/hooks` review.
- **Agents:** `.claude/agents` become Codex agent roles written under `$CODEX_HOME/compat/claude/<project>/agents/` and declared with `-c agents={…}` (`src/compat_agents.rs`).
- **Commands:** Claude Code's custom commands (`.claude/commands`, `~/.claude/commands`) and its skills, typed as `/name args`, are expanded by `src/compat_commands.rs` in the `Enter` hook and in print mode. A command's body gets its arguments; a skill becomes `$name args`. `CODEX_COMMANDS` is the list of Codex's own commands, which win; a test reads the pinned TUI's `SlashCommand` to keep it complete.
- **MCP servers:** Claude Code's MCP servers (`.mcp.json`, `~/.claude.json`) start only after `ling compat mcp approve`, by hash (`src/compat_mcp.rs`).
  - **stdio servers** run through `ling compat mcp-run`. It re-checks the approval, expands the variables Codex forwards by name, and at `/airgapped on` runs the server under `bwrap --unshare-net`.
  - **HTTP servers** are left to Codex and refused at `on`.
- **Permission rules:** Claude Code's permission rules and `--allowedTools`/`--disallowedTools` are enforced by `ling compat guard`, a trusted `PreToolUse` hook in the same table (`src/compat_permissions.rs`). Deny and ask refuse (ask cannot prompt in Codex); allow is the sandbox's. The guard **fails closed**: Codex lets a call through when a `PreToolUse` hook fails, so the guard's line ends in `|| <a printed refusal>` (`|| echo {…}` for cmd, `|| printf '%s\n' '{…}'` for sh), which answers deny when the guard cannot start, crashes or exits non-zero, and the guard itself refuses a call when it cannot read its input or decode a rule. A guard killed at the hook's timeout, which the fallback cannot answer, is blocked by patch `0032`, which makes a failed run of a hook whose command holds ` compat guard` a block. Print mode hands its rules to the child in `DREAMFERENCE_MIGHTLING_COMPAT_RULES`, and `--permission-mode` maps to Codex options in the TUI.
- **Start-up line:** a TUI start names what was read (`Claude Code files: CLAUDE.md n, hooks n, agents n`).

## Where edits land (worktree)

`src/worktree.rs`; spec `specs/DREAMFERENCE_MIGHTLING_WORKTREE.md`. In place by default, as in Codex. With `mightling-worktree-mode = "worktree"` in `[desktop]` of `$CODEX_HOME/config.toml` (written by `/worktree on`, `ling worktree on`; read by the desktop app's toggle too) or `DREAMFERENCE_MIGHTLING_WORKTREE=on`, a new interactive TUI session is moved before Codex parses its arguments: `git worktree add -b ling/<id> $CODEX_HOME/session-worktrees/<id>/<repo>`, a `session.json` beside it, `set_current_dir` into the same sub-folder and `-C` rewritten, all before anything reads the working folder (the code index, skills, the notice). Never `exec`, `resume`, `fork`, `review` or `app-server`, and Codex's own `--worktree` wins. `/worktree on|off|status|apply|discard` is answered by the `Enter` hook of patch `0029` (`compat_keys::enter` calls `worktree::enter` before its mode gate), so no patch bytes; `/worktree` alone stays Codex's picker. `apply` writes the worktree's whole state as a tree through a temporary `GIT_INDEX_FILE` and `git apply`s `base..tree` (or `applied..tree`) in the source after `--check`: uncommitted changes, all or nothing. `discard` keeps `refs/mightling/snapshots/<id>`. Each new interactive start prunes finished sessions that hold nothing (pid gone, checkout clean at its base or last apply). For a TUI session whose user set no `[tui] status_line`, the launcher passes `-c tui.status_line=[…]` with Codex's default items plus `git-branch`, so the footer shows the folder and the branch. `ling night apply <id>` uses the same `apply_between`.

## `CODEX_HOME` is `~/.mightling`, not `~/.codex`

`ling-rs/src/home.rs`, called first thing in Codex's `main()` by patch 0014, before `arg0` reads `.env` from the home folder. Upstream Codex keeps the vendor's sign-in in `~/.codex/auth.json`, and sharing the folder handed Mightling that login, and with it usage analytics, token refresh and the other channels to the vendor's backend. On first run the launcher copies an allow-list across (sessions, history, config, rules, skills, the session databases) and never `auth.json`, `installation_id`, `packages/` or the logs; the keyring is keyed by a hash of the home path, so it cannot leak the old login either. An explicit `CODEX_HOME` is respected. `CodexInstaller.home_dir()` mirrors the resolution for `ling-admin logs mcp`.

## Channels to the vendor, closed

- Patch 0013 disables the usage-analytics client where it is constructed, so no config or login can re-enable it.
- A traced session (strace on `connect`/`execve` plus reqwest debug logging) later showed more channels that need **no** login: OTEL metrics to Statsig at `ab.chatgpt.com` (Codex's default exporter in release builds, with an API key compiled in), `chatgpt.com/backend-api/plugins/featured`, a startup `git ls-remote https://github.com/openai/plugins.git`, and (TUI only) the upstream vendor's announcement tip from `raw.githubusercontent.com`. Patch 0015 closes each at its call site, and the launcher forces `chatgpt_base_url` to `http://127.0.0.1:9/backend-api/` so an undiscovered call to the vendor's backend fails locally.
- Patch 0012 hides `/import` (2026-10-19), which a typed command then cannot reach either: the importer's plugin step can `git clone` a marketplace or a plugin and `npm pack` a plugin (spec `specs/DREAMFERENCE_MIGHTLING_LING_CLAUDE.md` §16.4) inside `ling`'s own process. Since plugins are allowed at `/airgapped off` (2026-10-22) that alone would not keep it hidden, but the TUI command cannot follow a level switched mid-session without a patch, so it stays hidden. The desktop app's Import panel uses the same importer over the app server, and the bridge policy (`ling-rs/web/policy.json`, enforced by `ling web` and the app's main process alike) keeps plugin items at `off` and removes them at `on` (`airgappedRefusedImportItems`). The test is `ling_slash_import_is_hidden_and_refused` in `codex-tests/patches/0003-tests-hide-import.patch`.
- **Plugins** are Codex's own and allowed at `off` ([airgapped.md](airgapped.md#plugins)). What talks to the vendor stays closed: the curated catalogue's startup sync and featured list (0015), and the remote catalogue and plugin sharing, which the launcher switches off in `config.toml` (`features.remote_plugin` and `features.plugin_sharing`, forced like `chatgpt_base_url`; `plugins.rs`). The TUI's Curated tab, the vendor's marketplace, says it is closed (0030).
- **A trusted project's `.codex/config.toml` can replace the system prompt** (owner decision 2026-10-30, accepted; no Codex patch). `model_catalog_json`, `model_instructions_file`, `instructions`, `developer_instructions` and `experimental_compact_prompt_file` are not on Codex's `PROJECT_LOCAL_CONFIG_DENYLIST`, and the launcher names the `default` catalog only in the user's `config.toml`, so a trusted folder's file wins. It changes what the model is told, not what is enforced (air gap, sandbox, guards), and only a folder the user marked trusted can do it. The repository tier of `mightling_prompt` is the same class and specced (PROMPT §4.1). Documented in `docs/ling.md` beside the trust prompt.
- **A repository's `mightling_gmail = true` counts for nothing** (owner decision 2026-10-30). `mightling_gmail_enabled()` (`mightling_gmail_from_files`) and the Python tier (`_let_repository_turn_gmail_only_off`) take `true` only from the user's file or the environment; a repository's file can only turn Gmail off, and the user's file is read even when a repository's file shadows it.
- **A project's `.codex/config.toml` cannot reopen them** (2026-10-29). Codex reads a trusted folder's file above the user's `config.toml` and refuses only a short list of keys there (`chatgpt_base_url`, `model_providers`, `otel` and a few more), so `check_for_update_on_startup = true`, a `tui.pet` or `features.remote_plugin = true` in a repository would have turned a closed channel back on. Every session gets them as root `-c` settings, which sit above the project's file: `check_for_update_on_startup=false`, `tui.pet="disabled"`, `features.remote_plugin=false`, `features.plugin_sharing=false` (`plugins::vendor_settings`).
- Patch 0016 switches off `ling doctor`'s sign-in, update and reachability checks (GitHub releases, the upstream vendor's desktop feed, a hard-coded `chatgpt.com` URL the redirect does not cover, `api.openai.com`) behind `MIGHTLING_DOCTOR_OFFLINE`; the code stays, and setting the constant to `false` restores them.

That trace is now `ling-admin audit egress` ([egress-audit.md](egress-audit.md)), and `ling-admin codex build` runs it (and its `--tui` form) after installing a new binary (`--no-audit` skips it; without a model server it says so and does not wait): after a Codex bump, read its verdict.

## The share scope header

Every launch passes `-c model_providers.openai-custom.http_headers.X-Ling-Share-Scope="<hash>"` (`ling-rs/src/share_scope.rs`), so Codex sends `X-Ling-Share-Scope` on every request to the model server; it needs no patch, and a per-launch override rather than `config.toml` because the repository follows the working folder. The value is the first 32 hex characters of SHA-256 over the node id (else the user id) and the repository: the normalized `origin` URL, else the git toplevel's canonical path. Nothing readable leaves the machine. The engine (ling-serve, P4c) shares a cached prefix only between requests with the same scope, and requests without the header only with each other; SGLang and vLLM ignore the header. The launcher's own `/v1/models` calls carry none, as they touch no cache.

## Tests

The launcher's unit tests run with `cargo test --release -p ling-launcher` in the *export* directory under `~/.cache/dreamference/puffin-codex/`, never in `codex/`.
