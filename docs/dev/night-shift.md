# Night Shift

Developer notes behind the Night Shift line in `AGENTS.md`. Spec: `specs/DREAMFERENCE_MIGHTLING_NIGHT_SHIFT.md`, whose §11 records what was built.

Night Shift is two halves that share only files:

- **Queueing.** `/night add <task>` (patch `0018`, logic in `ling-rs/src/night.rs`; also `ling night …` from a shell) queues a task under `$CODEX_HOME/night/tasks/` and never calls the model.
- **Running.** `ling-admin night run` (`dreamference/night_shift/`, started by the `mightling-night.timer` user unit that `night enable` installs) works through the queue.

## How a task runs

- Each task runs `ling exec` in its own git worktree on `night/<id>`, inside a memory-capped systemd scope; the runner, not the agent, commits, and nothing is merged, pushed or rebased.
- **The commit's hooks run in the task's sandbox** (owner's decision of 2026-10-29): `commit_in_sandbox` makes a scratch repository under `<night>/scratch/` (alternates to the repository's objects, `include.path` to its config and the worktree's `config.worktree`, the worktree's index and branch), runs `git commit` and `git bundle create` in it through `ling sandbox` with the worktree and the scratch folder writable, the task's `/airgapped` level and its scope, and 300 s of its own past the task's deadline (`COMMIT_TIMEOUT_S`; output in `logs/<id>.commit.log`). The host copies the bundle with `O_NOFOLLOW`, unbundles it with no hook, checks that its one ref is a single commit on the branch's head and moves the branch. Every other `git` of the runner passes `core.hooksPath=/dev/null` (`NO_HOOKS`), so the runner's `worktree add` runs no `post-checkout`. A hook that refuses fails the task and keeps the worktree; a stop during the commit interrupts it. A remote task commits on the host with no hook, as a node job does. git 2.43 has no `fsck` for a bundle import; the host's own checks stand in. Signing the commit inside the sandbox may fail where the key agent's socket is not reachable.
- **Bringing a branch back** is the user's step: `ling night apply <id>` (or `/night apply <id>`, `night.rs`) applies `base..night/<id>` to the checkout it runs in as uncommitted changes, all or nothing, through `worktree::apply_between`, and records `applied` in the task; the report's Branch and Review lines, the TUI's start line and the desktop inbox name it (spec §11.10, MIGHTLING_WORKTREE §3.8).
- The runner's own test run executes what the agent wrote, so it goes through `ling sandbox` with a policy the runner fixes (workspace-write, no extra writable roots: the user's config makes `~/.mightling/skills` writable) and the task's `/airgapped` level, which is fixed once before the agent runs and exported to every command of the task. `[night] test_sandbox = false` is the user's opt-out.
- **Best-of-N** (`[night] best_of`, **3 by default** since the owner's decision of 2026-10-19 after SWE-bench night 13, 31/50 against a single run's 22/50, p = 0.022; a task's own `best_of`, which `/night add --best-of N` writes, outranks it; `1` is a single attempt as before; refused with `--on`): a task is attempted N times, one after another in worktrees `<id>-a<k>`, and chooser v1 (`NightShiftChooser`, shared with `scripts/swe_bench_chooser_test.py`) picks the attempt the runner commits as `night/<id>` (`NightShiftBestOfN`; spec §11.9). Resumed and remote tasks run once; interactive `ling` is never affected.
  - The chooser: the regression filter drops attempts whose test run failed or timed out (all go on if all did), one survivor is chosen outright, several go to the pairwise judge, a direct `/v1/chat/completions` call to the night's model server with chooser v1's prompt (what nights 11 and 13 measured; not a `ling exec` session). Without a test command the judge alone decides and the report says so.
  - The window bounds it: an attempt after the first does not start when less of the window is left than the longest attempt took, a judge call waits at most until the window's end (60 s at the least) and none starts after it, and the record's `why` says why fewer than N ran.
  - Every attempt keeps `logs/<id>-a<k>.jsonl`, `.test.log`, `.diff` and `.last.txt`; the report's `Why` line and per-attempt lines name them. Every attempt's worktree is removed and only the chosen branch is kept.
  - **Diverse attempts** (`[night] best_of_hints`, off by default; a task's own `best_of_hints` outranks it; the owner's idea of 2026-10-30): identical attempts fail on the same tasks (night 13: a single run's mean 48.7%, the oracle over three 72%), so attempt k > 1 gets strategy hint k-1 of `DEFAULT_HINTS` in `night_shift/strategy_hints.py` (six one-sentence hints about how to work, never about the answer: a reproduction first, every caller first, the cause not the symptom, the same bug elsewhere, the smallest change, the existing tests first), wrapping round, or of the list the setting gives instead of `true`. The hint is appended after the task as `Strategy for this attempt: …`, never before it, so the attempts share the prompt's prefix in the server's cache; attempt 1 has none and stays the single-run baseline, and with the setting off every prompt is byte-identical to before. The hint is recorded in the attempt's entry of the `best_of` record (`hint`) and in the report's attempt line. There is no automatic choice of hints, and `/night add` has no flag for it yet (a task's `best_of_hints` key works).
  - The tests' `setup` fixture in `tests/test_night_shift.py` pins `DEFAULT_BEST_OF` to 1; best-of-N's own tests are `tests/test_night_shift_best_of_n.py`.
- Both sides change a task only under `tasks/<id>.lock` (flock) and replace the JSON whole.
- The run never starts or loads the model server, gives way to an open `ling` session or an outside request, and `server start`, `codex build` and `index` refuse while it holds its lock.
- The launcher's guards (the test guard and the finish check, `mightling_test_guard` and `mightling_finish_check` in the config file; SWE_BENCH spec §29) apply to a night's `ling exec` sessions like any other once switched on; they are off by default. Their hook, `ling guard`, is not a session (`NON_INTERACTIVE` in `night_shift_host.py`).
- Before the first task the run refreshes each repository's code index (`ling-code index --exact --wait`, `night_shift_index.py`; `[night] index = false` switches it off).
- The desktop app's bundled `ling` is recognised as an app-server by name and `app-server` in its command line (`NightShiftHost._is_app_server`); see [desktop.md](desktop.md).
- A `ling` whose binary a build has since replaced is still recognised: `/proc/<pid>/exe` then reads `<path> (deleted)`, and `NightShiftHost.executable_of` drops that trailing suffix before comparing; the exact comparison missed a busy app-server after a rebuild and deleted its marker (found 2026-10-19).
- **Repeating tasks** (the owner's decision 7 of DESKTOP_PARITY §9.5, 2026-10-21; `night_shift_recurring.py`): templates under `night/recurring/r<12 hex>.json` (repository, task, test, cadence and parameters), made by `ling-admin night every add --daily|--weekly <day>|--days <days>|--every <N>|--monthly <D> [--test cmd] -- <task>` in the repository (one cadence a task; `night every --<cadence> …` is short for `night every add --<cadence> …`), listed and dropped with `night every list|drop`. `--days` takes `mon`…`sun`, comma-separated; `--every N` (1 to 365) is due the first night and then once N nights have passed since it was last queued, so a night without a run or a refused add moves the count rather than losing a turn; `--monthly D` (1 to 31) runs on the month's last day where the month is shorter (DESKTOP §16 B42). Each `night run` first queues the templates due that night through `ling night add` in their repository (one writer of task files, so best-of-N, the window and the report treat it as any task), at most once a day; a refusal is kept as `last_error` and tried the next night; what it did goes into the report's notes. The desktop app's Scheduled view repeats a task with any of the cadences, lists and stops repeating ones, opens a finished run on its result (`logs/<id>[-a<chosen>].last.txt`), changes (that attempt's `.diff`, else `git diff base..branch`) and transcript (its `ling exec --json` log), opens the run's session as a thread, and gives a task queued from a thread (or `/night add` there) the thread's latest messages as context (`desktop/ui/src/tonight.ts`).
- **The archive** (DESKTOP §16 B41; `night_shift_archive.py`, `NightShiftArchive.archive`): `ling-admin night archive [--weeks N]` (default 4, `DEFAULT_ARCHIVE_WEEKS`) moves finished tasks (`FINAL_STATUSES`) whose last history entry (else the file's time) is older than N weeks to `night/archive/tasks/`, each under its `tasks/<id>.lock`, with every `logs/<id>.*` and `logs/<id>-a<k>.*` of theirs; old logs whose task is gone and old reports (by file time) go too, into `archive/logs/` and `archive/reports/`. The archive is the queue's own layout, so the desktop app reads a run there as in the queue. Queued, running and interrupted tasks never move, a file the archive already holds is left in place (nothing is overwritten or deleted), branches stay, and the command refuses while a run holds `runner.lock` (it holds it itself, so no report is written meanwhile). `ling night apply` reads only `tasks/`, so an archived task's branch is applied with git. The desktop app's Scheduled searches the archive (`desktop/electron/src/nightinbox.ts` `searchArchive`), keeps each finished run unread until opened (the window preferences `nightSeen` and `nightRead`), counts the unread on Scheduled and in the tray, and drops its marks and thread ties of tasks gone from the queue for a day.
- **Autofill** (the owner's decision of 2026-10-28; `night_shift_autofill.py`, `AutofillCandidate`): `[night] autofill = true` (off by default; set it only on the box that runs Night Shift, third-puffin today) makes each `night run` queue up to `[night] autofill_max` (1 to 5, default 5) bounded tasks before it reads the queue, and `ling-admin night autofill [--dry-run] [--max N]` does the same by hand. Sources, in this order: failing tests of the latest failed CI run on `main` (`gh`; only strings shaped like `tests/...py::name`), failing checks of the latest desktop QA report (`~/.local/state/dreamference/qa/desktop/latest.json`) and the open "Windows QA failing" issue (number only, never its body: the repository is public), then unchecked `- [ ]` boxes and `TODO:` lines in `specs/*.md`. Each becomes an ordinary task through `ling night add` in `[night] autofill_repo` (default this checkout), whose first line is `[autofill:<key>]`, with the finding, "Acceptance test:" and the paths the agent must not touch; the runner's test command is the narrowest acceptance test (the failing test id; else the full suite). Skipped: a finding already queued or running, one queued in the last 14 days (the ledger `night/autofill.json`), anything whose key, title or detail mentions sandbox, bwrap, AppArmor, policy.json, sudo, sshd, signing, `.pem`, conftest, egress, codex-patches, airgapped, secrets or credentials, and every benchmark night (a SWE-bench run holds the runner lock, or a `ling-swe-*` unit is active). A failure of autofill is a note in the report, never a failed night. Nothing is merged or pushed; the result is the branch `night/<id>`.
- `[night] nodes` and `/night add --on <node>` use paired nodes; see [node.md](node.md).
- The sandbox needs the AppArmor profile when the run comes from the timer; see [host-safety.md](host-safety.md#bubblewrap-needs-an-apparmor-profile-and-this-machine-now-has-one).

## Morning review of autofilled tasks

For each task whose first line is `[autofill:<key>]` in the morning report (Claude agent or owner), in this order:

1. `git diff --stat main...night/<id>`: reject the branch at once if it touches `codex/`, `codex-patches/`, `tests/conftest.py`, `ling-rs/web/policy.json`, `ling-rs/airgapped/`, `.github/`, anything about the sandbox, sudo/sshd, signing or egress, or is much larger than the finding.
2. The task's `Acceptance test:` line: run it in a worktree of the branch (the report's test line says what the runner saw; do not trust it alone). The finding's own test must fail on `main` and pass on the branch.
3. Read the diff for the finding only: no unrelated refactor, no skipped or loosened test, no deleted check, and for a spec item that the spec line is ticked or dropped only if the work is complete.
4. Run the full suite on the branch; merge by AGENTS.md (`--no-ff` from a worktree), or delete the branch. Never `ling night apply` blindly.
5. A rejected finding comes back after 14 days; to stop it, drop the `TODO:` line or tick the box, or delete its key from `night/autofill.json` only to retry sooner.
