# The desktop app

Developer notes behind the desktop line in `AGENTS.md`. Spec: `specs/DREAMFERENCE_MIGHTLING_DESKTOP_ELECTRON.md`, whose §9 records what was built and measured.

The desktop app is Electron, built the way the Codex desktop app is built, with `ling` inside (`chat/desktop_runner.py`, project in `desktop/electron/`, Work's UI in `desktop/ui/`).

## Why Electron

Until 2026-10-07 it was a Tauri shell on the system's WebKitGTK, and typing into it on this GB10 trailed the keys: WebKitGTK's one GPU path asks the DRM device for a dumb buffer, which the proprietary NVIDIA driver refuses, so the app drew on the CPU at 40–50 ms per keystroke frame in a near-full-screen window (measured in an offscreen view, ELECTRON §1). Chromium renders through ANGLE on NVIDIA's own GL and never asks.

## Shape

- Electron is **stock 42.x, pinned to a patch release** (the Codex app runs the upstream vendor's own build of the same major). Forge 8 packages it (`maker-deb`; Forge 7 until 2026-10-09, ELECTRON §12); Vite builds the main process (`src/early-bootstrap.ts` → `bootstrap.ts` → `main.ts`) to `.vite/build/early-bootstrap.cjs`, the preload to `preload.cjs` (Forge 8 emits both as `.cjs`) and the page's React UI.
- `app.json` holds the product name, identifier, scheme and the window's settings (under `work`, its old name), read by the app and by the Python side alike.
- **One window, one app-server** (ASK §18.6, 2026-10-09). The app window is the app's only window and the `ling app-server` it starts the app's only one. Ask (the menu's former Chat, which showed the Onyx web UI until 2026-10-08) is a view of it: the menu's Ask and Work, the tray's, `ling app` and a second instance bring the window forward on the view asked for (`showView` in `main.ts`), and never open another. Until 2026-10-09 the menu's Ask opened a separate window on `ling web` (`chat.ts`, `web.ts`, now removed), whose own app-server shared `~/.mightling` with the window's; the app no longer starts, signs in to or loads `ling web`, which is unchanged for browsers.
- **The app window** (the former Work window) loads `app://-/index.html` from the asar (`app-protocol.ts`: a privileged scheme serving the bundle with a strict CSP, cancelling requests from any other origin) and talks to the main process over **one IPC channel** behind `window.electronBridge.sendMessageFromView`, answered only for that window's own `webContents`. It shows **Ask and Work** one click apart, as `ling web` does (`#work` opens Work; no argument opens Ask; the menu's Work entry, `--work`, a folder, a thread or a `mightling://` link open it on Work, and a `view` message switches the window when it is already open; ASK §18).
- **One policy for both hosts** (ASK §2.3): `policy.ts` compiles in `ling-rs/web/policy.json`, the file `ling web` compiles in, and `policy.test.ts` runs every case of `ling-rs/web/vectors/outgoing.json` with the shared stubs. The allow-list (a Python test checks it against the committed protocol types), the dropped thread fields, the named prompts, answers only to pending server requests. For an Ask thread the main process does what `ling web` does (`ask.ts`, `server.ts`): composes the named prompt with `ling prompt show <name> --composed` in `$CODEX_HOME/ask` before vetting, creates `ask/q-<hex>` (0700), confines the thread to it, links `ask/<thread-id>` to it once the server answers, and writes attachments there (`ask/upload`, base64 over the same channel, `ling web`'s caps and file-name rules). `bridge.ts` keeps `classify`, the busy marker Night Shift reads (`server.ts` writes it) and finding `ling`.
- `server.ts` spawns `<resources>/ling -c features.code_mode_host=true app-server` with `LOG_FORMAT=json`, `RUST_LOG=warn` and the resources folder on PATH, as the Codex app spawns its agent. `ling` and `codex-code-mode-host` are copied from the installed build into `desktop/electron/resources/` by `desktop build` (the release workflow takes them from the `ling` job's artifact) and ride along as extra resources.
- On a client, Ask runs in the app window on the app's own app-server, against the node's model server, which the bundled `ling` finds; the TCP forwarder to the node's port 3000 and the app's own node discovery were removed with the Onyx window; see [node.md](node.md).

## Six things to keep

1. **No GPU switches, no `WEBKIT_*`, no `GTK_THEME`, no `--no-sandbox`**: Electron's defaults, as the Codex app runs. A test greps the sources for each.
2. **Chromium's sandbox needs a user namespace, and Ubuntu refuses one to programs without an AppArmor profile** (the same `kernel.apparmor_restrict_unprivileged_userns` rule as `bwrap`, see [host-safety.md](host-safety.md#bubblewrap-needs-an-apparmor-profile-and-this-machine-now-has-one)). The `.deb`'s `postinst` writes `/etc/apparmor.d/mightling` (`profile mightling "/usr/lib/mightling/Mightling" flags=(unconfined) { userns, }`, the Codex app's shape) and loads it; `prerm` removes it; **no `chrome-sandbox` SUID helper is shipped** (the packager's `afterCopy` deletes it). For a checkout, `desktop install` writes `mightling-desktop-dev` for npm's `electron` and the packaged binary, with sudo, announced first. From a terminal under PyCharm's permissive profile the app starts without any of this, which is why the problem only shows from the launcher or a plain terminal: `DesktopInstaller.userns_allowed()` asks as an unconfined program would (`aa-exec -p unconfined`).
3. **Egress is closed in the main process and checked by `ling-admin audit egress --app`.** `egress.ts` always passes `disable-background-networking`, `disable-component-update` and `disable-features=AimEnabled,AutofillServerCommunication,NetworkTimeServiceQuerying,MediaRouter`; permission requests are denied except clipboard writes and the microphone, audio only, for the app's own page (`grantsRequest`; dictation, ASK §7: the recording goes to the main process as `voice/transcribe`, which posts it to the speech-to-text sidecar on `127.0.0.1:8100`); `app://-/images/<id>.jpg` serves the image search store read-only (`imageFile`, ASK §6); the spellchecker's dictionary download is pointed at `app://` (so it fails locally) and `window.open` goes to the system browser. Fuses: `RunAsNode`, `EnableNodeOptionsEnvironmentVariable`, `EnableNodeCliInspectArguments`, `GrantFileProtocolExtraPrivileges` off; `EnableCookieEncryption`, `EnableEmbeddedAsarIntegrityValidation`, `OnlyLoadAppFromAsar`, `WasmTrapHandlers` on; flipped by a `postPackage` hook with `@electron/fuses` 2, because Forge 7's own fuses plugin pinned the 1.x line, which has no `WasmTrapHandlers` (Forge 8's takes 2.x; the hook stays, since it also deletes `chrome-sandbox` and re-signs a Mac bundle). The audit's app mode starts the packaged (or installed) app as `ling app` does, with no argument and `MIGHTLING_APP_AUDIT=<seconds>` (the window hidden on Ask, its app-server started, quit by itself), in a scratch `HOME` and `CODEX_HOME`, with the `exec` session's allowlist: since the fold a connect to `ling web`'s 3100 is a finding, as one to Onyx's 3000 is; it needs a display (`DISPLAY` or `xvfb-run`), because Electron's `--ozone-platform=headless` SIGSEGVs on this machine.
4. **The data folder stays `~/.local/share/dev.dreamference.mightling`** (`app.setPath("userData", …)` after `app.setName`), so `ling app` keeps emptying the HTTP cache there (now Chromium's `Cache`, never its `Cookies`) and the rename migration's move still lands. The window's bounds are persisted beside it (`window-state.ts`, clamped to a display's work area).
5. **The app window is frameless with native controls** (`titleBarStyle: "hidden"`, a transparent `titleBarOverlay`, 36 px), so the page's own header bar is the title bar: `-webkit-app-region: drag` on `.bar`, `no-drag` on its controls, and 150 px of right padding under the overlay's buttons, all under `html[data-host="electron"]`, since `ling web` serves the same page to browsers and phones.
6. **The app signs in to nothing and handles no password.** Its app-server is its own child on stdio, so there is no session to hold. The Onyx password sign-in (`sign-in.ts`) went with the Onyx window and the `ling web` one-time link (`ling web open --print-url`, which `ling web` still offers) with the separate Ask window; `credentials.test.ts` checks that no bundle, the main process's included, carries a credential string or that link.

## Also

- **`ling airgapped --thread <id>`** is how Work learns a thread's air-gap level (`airgapped.ts` parses the first line): the launcher's own resolver, not a fourth copy of the crate.
- `ling-admin desktop {install,run,build,status}` needs **Node 22.13+ and npm only** (Forge 8's floor; and `dpkg` for the `.deb`, no `fakeroot`); `desktop run` packages the app and runs the packaged binary, never `electron-forge start`, whose dev server Work's `app://` page does not use.
- Night Shift recognises the `ling` bundled inside the app as an app-server by name and `app-server` in its command line, not only the installed binary (`NightShiftHost._is_app_server`).
- `DesktopInstaller`'s rustup helpers stay because the Codex build drives them.
- `DesktopRunner.has_source()` tells a checkout from a release install ([install-modes.md](install-modes.md)).

## Phase 2 (DESKTOP_PARITY §4.2)

- **The window's preferences** (`desktop/electron/src/prefs.ts`): one `prefs.json` under the data folder, mode 0600, every key and value checked against `desktop/ui/src/prefs.json`, the schema the page is built with (`prefs/read`, `prefs/write` over the one channel); a browser on `ling web` keeps the same keys in `localStorage`. Window settings only: agent settings stay in `~/.mightling/config.toml`, written by the server.
- **The keymap** is data (`desktop/ui/src/keymap.json`, §2.19 with a `built` or `planned` status per action); handlers name their action with `keyAction("<id>")` and `keymap.test.ts` holds the table and the code together.
- **The composer** (item 4): `composer.ts` (completion triggers, slash commands, prompt history, the approval keys), `turns.ts` (steer, queue, take back, fork over the RPC client), `ComposerView.tsx`. A Shift+dragged image is sent by its path, which the preload reads with `webUtils.getPathForFile` (`electronBridge.pathForFile`); `/airgapped default <level>` runs `ling airgapped default` in the main process (`work/airgapped-default`).
- **Window-side git** (item 6, `desktop/electron/src/git.ts`): `git` with an argument list (never a shell), `GIT_TERMINAL_PROMPT=0`, output capped at 16 MB; a repository is accepted only as its own top level, paths only inside it, a hunk patch only on stdin and only if its headers stay inside; `push` and the pull-request page are refused at `/airgapped on` (main.ts asks `ling airgapped --thread`). Nothing runs `git` at start-up, so the egress audit's app session sees none. Editors: `editors.ts`. The review pane is `ReviewPane.tsx` over `diff.ts`; a generated commit message is an ephemeral, read-only thread (`turns.ts` `askOnce`).
- **Worktrees and hand-off** (item 7, `worktree.ts`): the `codex-worktree` crate's contract step for step from the main process (`$CODEX_HOME/worktrees/<4 hex>/<repo>`, detached, `core.worktree` in `config.worktree`, `codex-thread.json`), plus snapshots under `refs/mightling/snapshots/` before a removal or a hand-off, `.worktreeinclude`, and the hand-off itself. A removal is refused unless the checkout is one of the source's managed worktrees. Which thread works where is a window preference (`worktreeThreads`); later turns carry `cwd`. Settings › Worktrees writes `[desktop]` in `config.toml` through the server, the keys the crate reads.
- **Local environments and tasks** (item 7, `environments.ts`, `tasks.ts`): read from `.codex/` and `.mightling/`, written to `.mightling/` only (`smol-toml`); setup and actions run in the user's shell as bottom-panel tasks, each its own process group, refused at `/airgapped on`.
- **The shell** (item 2, `shell.ts`, `CommandMenu.tsx`, `SettingsDialog.tsx`): the page handles every shortcut from `keymap.json` with the user's overrides (`keyOverrides` in the window's preferences, applied as the page renders); the Electron menu only shows keys (`registerAccelerator: false`), so Ctrl+W never closes the window. Back/forward, undo/redo of archive and rename, CSS zoom for the text size.
- **Pop-outs** (item 3, `windows.ts`): several windows on the one app-server; the main process tags each window's request ids (`<webContents id>␟<id>`), returns each answer to its window, broadcasts notifications and server requests, and answers a later window's `initialize` with the first one's result. Only the app's windows may use the channel (`windowFor`). Links: `ling://` and the older `mightling://` (`app.json` `scheme`, `legacySchemes`).
- **Terminal tabs** (item 8, `terminal.ts`, `TerminalView.tsx`): xterm.js over `command/exec` with `tty` under the composer's permission profile; the hub routes `command/exec/outputDelta` by `processId` and keeps what arrives before a tab is drawn. `thread/shellCommand` stays out of the policy (it runs unsandboxed).
- **Held work** (2026-10-17, landed 2026-10-18 as 1d9eb48): what needed new methods in `policy.json` waited on `desktop/p2-held` for `cargo test --release -p ling-launcher -p ling-web-server` in the export with its `ling-rs/`; a policy change lands only after that run.
- **Methods still to add** to `policy.json` are listed, with their item, in `tests/test_desktop_parity.py` (`POLICY_TO_ADD`); adding one needs the Rust conformance run, so it never lands while a SWE-bench night owns the machine.

## Phase 3 (DESKTOP_PARITY §4.3)

- **The tab area** (`TabArea.tsx`, `tabs.ts`): Review and file tabs in one strip, every tab kept mounted (the ones behind hidden); Ctrl+W closes the tab in front and Ctrl+Shift+T reopens it. **File tabs and the file tree** (item 1, `FileTree.tsx`, `FileView.tsx`, `files.ts`): read only, through the server's `fs/readDirectory|readFile|watch|unwatch` (the policy refuses `fs/writeFile` and `fs/remove`); open folders and open files are followed with `fs/watch`; highlight.js core with twenty bundled languages; a file over 4 MB asks before it is read (`file/size`, a stat in the main process; a browser on `ling web` has no such guard).

## Tests

- `npm test` in `desktop/electron` (vitest, the main-process modules; `policy.test.ts` runs `ling web`'s conformance cases; `ask.test.ts` runs an Ask thread through `AppServer` against a scripted `ling`) and in `desktop/ui`.
- `npm run e2e` (Playwright-Electron, needs a display and `npm run package` first): no argument opens the one window on Ask, the menu's Work and Ask switch it without opening another, and only one app-server and no `ling web` is ever started; Work on `app://`; and an Ask question with an image through the real main process against a scripted `ling`.
- `desktop/ui/src/styles.test.ts` guards the look (DESKTOP_PARITY §3): the `:root` tokens, light only (no dark block, no `prefers-color-scheme`; dark not approved 2026-10-16), no remote URL in the stylesheet and every `url()` a bundled font, and the licences beside the fonts (OFL) and the icons (ISC). Vitest empties CSS unless asked, hence `css.include` in `desktop/ui/vite.config.ts`.
- `MIGHTLING_LOOK_DIR=<folder> npm run e2e -- look` (after `npm run package`) saves Ask (empty and with a question) and Work (a command, a diff, an approval) as PNGs, against a stand-in with made-up threads; without the variable the test is skipped. It sets the system theme dark through `nativeTheme.themeSource`, so the pictures show the app stays light, turns transitions off (a window the compositor thinks is covered can freeze one at its first frame) and parks the pointer before each picture.
- `npm run e2e -- phase2` (after `npm run package`) runs one test per Phase 2 item against `e2e/stand-in.ts`, a scripted `ling app-server` with made-up threads under a scratch HOME; with `MIGHTLING_LOOK_DIR=<folder>` the window is shown and each item's pictures are saved there.
- `tests/test_desktop_parity.py`: the protocol inventory (`desktop/ui/src/protocol-inventory.json` against the committed types and, with the submodule, the pinned schema) and the policy coverage of §2's Phase 2 rows.
- The Python tests read `app.json`, `forge.config.js`, `linux/postinst` and the TypeScript sources as text.
