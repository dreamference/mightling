# Phone messengers: `ling signal`, `ling chat`, `ling-admin matrix`

Specs: `specs/DREAMFERENCE_MIGHTLING_SIGNAL.md` (§16–§17) and `specs/DREAMFERENCE_MIGHTLING_CHAT.md` (§14–§15) record what was built and verified. The user page is `docs/messengers.md`.

**Phone messengers ship with Mightling and are off until a command turns one on** (specs `specs/DREAMFERENCE_MIGHTLING_SIGNAL.md` §16 and `specs/DREAMFERENCE_MIGHTLING_CHAT.md` §14 record what was built; user page `docs/messengers.md`). There is one command surface, `ling`: `ling signal …` and `ling chat …` are launcher subcommands like `ling web`, and the only `ling-admin` part is `ling-admin matrix …`, because containers are `ling-admin`'s. Every bridge is a client of `ling web`, so a message becomes an Ask thread under the same bridge policy, and each is its own process, because it needs the network and `ling web` promises it calls nothing on any network. Nothing is started, listens or registers until `ling signal setup`, `ling chat start` (after `ling chat telegram setup` or `ling-admin matrix start`) or `ling-admin matrix start`; their `stop` commands *disable* the unit, so off survives a reboot; and `ling-admin audit egress` names each one that is on as a declared exception (`EgressAudit.declared_exceptions`: the system unit `mightling-signal.service`, the user unit `mightling-chat.service` with a Telegram token, the user socket `mightling-matrix-proxy.socket`), never passing it silently. Five things to keep:
- **Signal is linked to the owner's own account and reads Note to Self alone** (crate `ling-rs/signal/`, `ling-signal`). The launcher links the crate for `ling signal …` (`ling-rs/src/signal.rs`, Linux only); the crate also builds a **small `ling-signal` binary**, the daemon the system account `mightling-signal` runs from `/usr/local/lib/mightling` (users' homes are 0750, and the 300 MB `ling` with its home folder and rename migration is the wrong thing to run as a system account). It is built in the same Cargo run as `ling` (`BUILDS_SIGNAL` in the builder), shipped as the optional release asset `ling-signal-<target>.gz`, installed beside `ling` and **never linked onto PATH**; `ling signal setup` copies it for the account and `ling signal setup --refresh` copies it again after `ling update`. The bridge's own commands (`serve`, `init`, `retool`, `pair`, `bind`, `trust-owner`) are accepted only from that binary.
- **signal-cli and Java are fetched by setup, pinned by URL and SHA-256, never bundled**: signal-cli 0.14.9, libsignal's arm64 JNI build 0.103.0 (signal-cli ships x86_64 only) and Eclipse Temurin's JRE 25.0.4.1+1, each checked as the user before it is unpacked as root under `/opt/mightling` (`ling-rs/signal/src/setup.rs`), the way `ling-admin docs setup` fetches ling-docs's runtime. No apt package for Java: a pool URL vanishes when a security update supersedes it.
- **`ling chat` is one bridge with two adapters** (crate `ling-rs/chat/`, `ling-chat`, linked into `ling`): **Matrix**, private, against the user's own tuwunel homeserver (`dreamference/chat/matrix_homeserver.py`, image pinned by digest) on an **internal Docker network** with no route out, reached by the host through `systemd-socket-proxyd` user units on `127.0.0.1:6167` and by the phone through `tailscale serve`; and **Telegram**, less private, by long polling, with consent typed at a terminal. The tailnet name becomes the Matrix server name, which is permanent: `start` refuses when Tailscale reports another. The hub signs in to `ling web` as `ling web ask` does, so a restarted `ling web` just means signing in again.
- **The air gap**: Signal acts only at `/airgapped off` (read through `ling web`'s `/api/airgapped`, since the system account cannot read the user's config) and Telegram pauses at `on`; Matrix, which never leaves the machine, keeps working.
- **Tests**: `cargo test --release -p ling-signal -p ling-chat` in the scratch export (the release job does the same), against a scripted signal-cli, a stand-in `ling web`, Bot API and homeserver, plus one test through the real `ling-web-server`; the Python side's only ways out are `MatrixHomeserver._run` and `_http`, both replaced in its tests. Nothing has been run against real Signal, Telegram, Matrix or Tailscale.
